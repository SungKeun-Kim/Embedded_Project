# 트랜스듀서 감지 시간 변경 및 검증 기록

작성일: 2026-10-14 / Firmware V1.2.0

## 변경 사항

- include/params.h의 TRANSDUCER_SIGNAL_LOSS_HOLD_MS: 1000ms → 2000ms.
- 실제 PA7 출력 50% 이상에서 PA6 신호 peak 진폭이 50 ADC count 미만인 상태를 200ms 단위로 10회 연속 감시.
- 정상 신호 또는 50% 미만 출력이 검출되면 누적 초기화. Local/PLC 운전 모두 적용.
- START부터 정확히 2초가 아니라 실제 출력이 50% 이상이 된 이후 무신호 약 2초를 감시. Soft Start 1.5초 유지.
- 과전류: 200ms RMS 결과 5개의 이동평균(1초 평균)이 7.00A 이상으로 약 5초 유지될 때 정지. 기존 조건 확인, 변경 없음.
- program_update.bat에 출력 STOP 및 외부 RUN OFF 확인 추가.
- PLC Markdown 가이드의 트랜스듀서 보호 시간 설명 갱신.

초기 HEX 생성에서 PATH의 objcopy 누락이 있어 설치된 GNU 도구 경로를 지정해 재실행했고 성공했다.
링커는 기존 구성의 LOAD segment RWX 경고 1건을 출력했다. 빌드 오류와 시험 실패는 없다.
기존 빌드 절차가 Factory HEX도 자동 생성하지만 이번 보드 업로드 및 ZIP에는 UPDATE HEX만 사용한다.

## 연결 보드 업로드

STM32CubeProgrammer CLI 2.23.0, ST-LINK V2J47S7, SWD 100kHz 사용.
장치 ID 0x469, Flash 128KB, Target voltage 약 3.14V.

| 항목 | 결과 |
| --- | --- |
| 업로드 전 출력 정지 확인 | PA15/SONIC_ON=LOW, PC13/GOING=LOW |
| 업로드 전 외부 시작 입력 | PA10/REMOTE=HIGH(비활성) |
| 업로드 전 백업 | Flash Bank 1 64KB 읽기 완료 |

| Reset | MCU Reset / Software reset is performed |
| Run | Core run, CLI 종료 코드 0 |
| 설정 Page 비교 | 0x0800F800~0x0800FFFF의 2048 bytes 업로드 전후 완전 일치 |
| 실행 상태 확인 | g_us_state.running=0, error_active=0, PA15/PC13=LOW, HAL tick 증가 확인 |

설정 Page SHA-256: be32e00179ef5b91ffdfa2678c3248e0ad966c116ecdc0c1b2d049f26ae0c6de

업로드 후 HAL tick은 0x0000E9C4 → 0x0000E9E5로 증가했다.
Full chip erase와 Factory HEX 기록 및 Option Byte 변경은 수행하지 않았다.
현장 로그와 보드 백업은 production/update_20261014_logs에 보관한다.
이 로그/백업은 다른 보드용 ZIP에 넣지 않는다.

## 실제 부하 시험 범위

PC 논리 시험과 ST-LINK Writing/Verify/Reset/Run을 확인했다.
실제 트랜스듀서 부하에서 메시지 발생 시간과 외부 전류계 대비 정확도를 측정하는 시험은 수행하지 않았다.
LCD 화면은 현장에서 확인해야 한다.
업데이트 파일은 기존 사용자 설정을 보존하며, 배포 ZIP의 SHA256SUMS.txt로 반영본을 구분한다.
