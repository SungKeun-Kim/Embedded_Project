# 정지 후 PA7 PWM 잔류 차단 수정

작성일: 2026-10-14

이 문서는 1차 PA7 차단 수정 이력이다. 현재 production의 UPDATE HEX는 후속
[GDT 일반 정지 시험본](GDT_일반정지_시험본_20261014.md)이며, 아래 SHA-256과
구현 설명은 1차 수정본에 해당한다. 해당 바이너리는 후속 작업의 source_before에 보관했다.

## 확인된 문제

37.7 kHz 구동 후 STOP 시 IRFP460 출력단에서 잡음이 섞인 약 12.4 kHz가 관측된다는
현장 증상을 바탕으로 코드를 점검했다. 실제 출력단 파형과 GDT 기생 발진은 아직
측정하지 않았으므로, 이 수정으로 해당 현상이 해결됐다고 판정하지 않는다.

기존 일반 Stop의 `UltrasonicPWM_SetDuty(0)`은 PA7에 0%가 아닌 5% PWM을 출력했다.
이후 main loop의 PB1 갱신, PLC 출력/제어권 변경 및 오류 Reset도 대기 중 PA7에
운전 지령을 다시 쓸 수 있었다. 보호 정지의 CCR2=0 쓰기도 preload 갱신 전까지는
기존 펄스가 남을 수 있었다.

## 적용 내용

| 상황 | 수정 후 동작 |
| --- | --- |
| 부팅/초기화 실패 | PA7은 GPIO LOW. TIM3의 0% 및 강제 LOW 준비 성공 후 AF로 전환 |
| 일반/보호/타이머 정지 | SONIC_ON LOW → PA7 강제 LOW 및 CCR2=0 즉시 갱신 → HRTIM 출력/카운터 정지 |
| 정지 중 PB1/PLC 출력·제어권 변경 | 목표값만 저장, PA7은 LOW 유지 |
| 정지 중 하위 SetDuty 직접 호출 | 출력 시작 상태가 아니면 LOW 유지 |
| 오류 Reset | 전체 차단 유지. Reset 자체로 재시작하지 않음 |
| Pulse OFF | PA7 실제 0%. HRTIM/SONIC_ON은 Pulse 운전 상태 유지 |
| 다음 Start | 시작 성공 시에만 PA7 5%부터 기존 1.5초 소프트 스타트 적용 |
| HRTIM 시작 실패 | 전체 차단, RUN/GOING 진입 금지, OUTPUT ERROR latch |

- PA7은 TIM3의 forced inactive 모드로 LOW를 구동한다. 채널을 단순 Disable하여
  Hi-Z로 만드는 방식은 사용하지 않는다. CCR2=0은 update event로 함께 반영한다.
- HRTIM 정지에는 ODISR/MCR 직접 쓰기를 사용해 HAL lock/HAL_BUSY로 차단을 건너뛰지 않는다.
- 새 `ERROR_CODE=3`은 출력 초기화/시작 실패이다. 기존 0/1/2 코드 값은 유지한다.
- 정지 중 PA7과 HRTIM 단일 채널 잔류, SONIC_ON 상태를 자기검증에 포함했다.
  이 자기검증은 현재 main의 진단 결과 생성 기능이며, 별도 하드웨어 차단 장치는 아니다.
- 운전 주파수, GDT dead-time, 보호 감지 시간과 Flash 설정 형식은 변경하지 않았다.

## 검증 결과

- Release Build 성공: text 50,600 bytes, data 168 bytes, bss 8,736 bytes.
- `test_host` 전체 7개 Python 시험 스크립트 통과. 기본 수치 시험은 37/37 통과.
- 새 출력 차단 시험은 실제 C 소스의 차단 호출 경로, 정지 후 재출력 방지,
  부팅, Reset, Pulse 및 시작 실패 처리의 정적 계약을 검사한다.
- 호스트 시험은 실제 MCU 실행/파형 검증이나 HAL 실패 주입 시험이 아니다.
- UPDATE HEX의 각 레코드 checksum, EOF, 주소 중복 없음, 빌드 산출물과 동일함을 확인했다.
- UPDATE 데이터 범위: `0x08000000..0x0800C657`.
- 설정 Page `0x0800F800..0x0800FFFF`는 UPDATE HEX에 포함되지 않는다.
- 기존 빌드에도 있던 linker `LOAD segment with RWX permissions` 경고 1건이 유지된다.
- 첫 빌드의 objcopy PATH 누락은 설치된 ARM 도구 경로를 프로세스 PATH에 추가해 해결했다.

## 업데이트 파일과 현장 확인

사용 파일: [US_MAIN_BOARD_UPDATE_V1.2.0.hex](US_MAIN_BOARD_UPDATE_V1.2.0.hex)

SHA-256:
`e6399ce0674e32890db928bc89919bf2e342ac150e667bed1a194ea962126659`

기존 FIELD_UPDATE 폴더/ZIP은 이전 배포본이다. 이번 검증에는 위 파일을 사용한다.
수정 전 주요 소스와 UPDATE HEX는 `stop_pwm_fix_20261014/source_before/`에 보관했다.
2026-10-14 사용자에게 출력 STOP 및 REMOTE/PLC RUN OFF 완료를 확인받은 뒤
연결 보드에 Writing, Verify, Reset/Run을 완료했다. 오실로스코프 실측은 아직 수행하지 않았다.

### 보드 업로드 결과

- STM32CubeProgrammer v2.23.0, SWD 100 kHz, Under Reset 연결.
- ST-LINK SN: `3B130913A218303030303032`.
- MCU 식별: Device ID `0x469`, STM32G47x/G48x/G414, Revision X, 128 KB.
- UPDATE HEX Writing 성공, `Download verified successfully` 확인.
- application에 해당하는 sector 0~24만 erase. Full chip erase/Factory HEX 사용 없음.
- 설정 Page 2,048 bytes를 업로드 전후 읽어 SHA-256 일치 확인:
  `55b413ce652668226e947c1b4ec50aa707d6b5fdcb2bf0fa372225b8efa6b448`.
- `Software reset is performed`, `Core run` 확인. CLI 종료 코드 0.
- 로그: [Writing/Verify](stop_pwm_fix_20261014/upload_write_verify.log),
  [설정 보존](stop_pwm_fix_20261014/settings_preservation.log),

### 현장 파형 확인 절차

1. 초음파 출력을 정지하고 외부 REMOTE/PLC RUN 지령을 OFF로 둔다.
2. UPDATE HEX로 Writing 후 Verify와 Reset/Run 결과를 확인한다.
   Full chip erase와 Factory HEX는 사용하지 않는다.
3. 부팅/STOP 후 PA7이 LOW로 유지되는지 확인한다. 정지 상태에서 볼륨 조정,
   PLC 출력값 변경, 제어권 전환 및 오류 Reset을 해도 펄스가 없어야 한다.
4. Start 시 기존 3 kHz PWM과 소프트 스타트가 복귀하고, STOP 시 PA7과 두 IR2104의
   SD가 LOW로 유지되는지 정지 순간을 캡처한다. 외부 출력 조절 회로도 0% 입력을
   실제 OFF로 처리하는지 확인한다.
5. 이 조건에서도 IRFP460 출력단의 이상 파형이 지속되면 각 MOSFET의 실제
   Gate–Source 파형과 출력 전류를 확인한다. GDT/게이트 방전/기생 턴온 문제는
   소프트웨어 차단만으로 해결됐다고 볼 수 없다. 고전압부는 정격에 맞는 차동
   프로브를 사용한다.

판정 기준은 12.4 kHz 자동 측정값의 유무만이 아니라, 정지 후 제어 펄스 차단,
게이트 OFF 유지, 출력 전류 소멸 및 반복 시작/정지 시 재발 여부이다.
