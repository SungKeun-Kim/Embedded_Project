# GDT 일반 정지 시험본 — 2026-10-14

## 목적과 적용 조건

PA7 차단 수정 후 잔류 출력이 줄었으나, 반복 ON/OFF 시 정지 후 파형이 달라지고
콘덴서 방전과 함께 서서히 사라진다는 관측에 따라 일반 정지 과정을 일정하게 만든다.
GDT 기생 발진이 원인이라는 확정 진단은 아니며, 파형 개선 효과와 200 us 유지시간의
적정성은 실제 GDT 1차/IRFP460 Gate–Source 측정으로 확인해야 한다.

현재 프로젝트 회로 기준: PA8/PA9 → 비반전 74AHCT125 → 두 IR2104의 IN,
PA15 → 공통 SD, 두 하프브리지 중점 → GDT 1차 양 끝.
SD HIGH 상태에서 두 IN이 LOW이면 두 앞단 low-side가 ON되어 1차를 0 V로 잡는다.
IRFP460 출력단의 두 소자를 동시에 켜는 제어가 아니다.

## 변경된 정지 순서

1. 일반 STOP/타이머 만료 시 Sweep ISR을 정지하고 PA7을 즉시 LOW로 강제한다.
2. 하위 출력 상태를 정지로 바꿔 SetDuty로 PA7을 다시 켤 수 없도록 한다.
3. Timer A의 counter rollover를 폴링한다. 검출 중에만 IRQ를 잠시 막는다.
4. rollover 직후 dead-time의 앞 절반 이내에 관측했을 때 TA1/TA2를 ODISR 한 번의
   쓰기로 함께 IDLE LOW로 전환하고 Timer A counter를 정지한다.
5. IRQ를 복원한 뒤 SD HIGH 상태를 DWT 기준 200 us 더 유지한다.
6. 기존 즉시 Stop 함수를 호출해 SD LOW/PA7 LOW/HRTIM 차단 상태로 끝낸다.

주파수 37.7 kHz의 주기는 약 26.5 us이다. 정상적으로 경계 검출이 되면 경계 대기는
한 주기 이내이며, LOW 유지시간 200 us가 추가된다. 소프트웨어 폴링이므로 정확한
에지 지연은 실측이 필요하다. IRQ가 개입하면 유지시간이 늘 수 있다.

`GDT_STOP_CLAMP_US=200`, `GDT_STOP_SYNC_TIMEOUT_US=100`은 `include/params.h`에 있다.
이 지연은 콘덴서 전체의 방전 완료를 기다리는 시간이 아니다.

## 실패 및 보호 경로

- 과전류/트랜스듀서 오류, 시작 실패, 오류 Reset은 대기 없는 기존 Stop을 사용한다.
- 일반 정지에서도 미초기화/이미 정지/DWT 미준비/ISR 또는 IRQ 차단 상태 호출,
  counter 정지/SD LOW 등의 경우에는 곧바로 기존 Stop을 사용한다.
- 경계가 늦게 관측되거나 DWT 기준 100 us 안에 검출되지 않으면 즉시 Stop한다.
- DWT가 동작 중 멈추는 경우도 유한 반복 제한으로 빠져나온다. 이 경우의 제한은
  반복 횟수이며 100 us의 정확한 시간 보장은 아니다.
- 정지 경로는 SD나 HRTIM 출력을 다시 활성화하지 않는다. 유지 중 외부 보호가 SD를
  LOW로 만들면 유지 대기도 종료한다.
- 재시작 전 Timer A counter를 0으로 초기화한다. 운전 중 주파수/dead-time은 유지한다.
- `s_gdt_stop_clamped_count`, `s_gdt_stop_fallback_count`는 디버거 확인용 누적값이다.
  후자는 경계 대기를 시도했다가 실패한 횟수이며, 사전 조건 실패는 포함하지 않는다.

## 검증

- Release Build 성공: text 50,976 / data 168 / bss 8,744 bytes.
- `test_host` 전체 8개 스크립트 통과, 기본 수치 시험 37/37 통과.
- 새 GDT 시험은 실제 C 소스의 보호/일반 정지 분리, 재활성화 금지, 시간/반복 상한,
  IRQ 복원과 실패 시 차단 경로를 검사한다. HAL 실패 주입이나 파형 에뮬레이션은 아니다.
- 생성 ARM 명령어에서 경계 비교 후 ODISR 동시 쓰기, MCR 정지, IRQ 복원 및 최종
  즉시 Stop 호출을 확인했다. 전기적 지연이나 감쇠 효과를 검증한 것은 아니다.
- 기존 linker RWX LOAD segment 경고 1건 유지, 새로운 컴파일 경고 없음.
- UPDATE HEX의 checksum/EOF/주소 중복 없음/빌드 파일 일치 확인.
- 데이터 범위 `0x08000000..0x0800C7CF`, 설정 Page `0x0800F800..0x0800FFFF` 제외.

## 업로드와 현장 확인

사용자가 출력 STOP 및 REMOTE/PLC RUN OFF 상태 유지 중임을 확인한 뒤 업로드했다.

- STM32CubeProgrammer v2.23.0, ST-LINK `3B130913A218303030303032`, SWD 100 kHz.
- Device ID `0x469`, STM32G47x/G48x/G414, Revision X, 128 KB.
- Application sector 0~24만 erase 후 Writing 성공.
- `Download verified successfully`, `Software reset is performed`, `Core run` 확인.
- 설정 Page 2 KB를 전후 읽어 SHA-256 동일함을 확인했다:
  `3baf4f3613e27b6c5f1743b736ae4cd745f3bac8c34108da4da91ae050fc748c`.
- Full chip erase와 Factory HEX는 사용하지 않았다.
- 로그: [Writing/Verify](gdt_stop_fix_20261014/upload_write_verify.log),
  [설정 보존](gdt_stop_fix_20261014/settings_preservation.log),
  [Reset/Run](gdt_stop_fix_20261014/upload_reset_run.log).

Reset/Run 후 `mode=HotPlug`로 발진을 시작하지 않고 대기 상태를 읽어 확인했다.
이 값은 해당 ELF의 심볼 주소 기준이며 이후 빌드에서는 주소가 달라질 수 있다.

| 확인 항목 | 읽은 값 | 해석 |
| --- | --- | --- |
| RAM `0x20001574` | `0x01010100` | output_running=0, stop_clock_ready=1, phase_ready=1, ready=1 |
| TIM3 CCMR1 | `0x00004800` | CH2 forced inactive, preload 활성 |
| TIM3 CCR2 | `0x00000000` | PA7 듀티 0 |
| HRTIM OENR | `0x00000000` | HRTIM 출력 비활성 |
| GPIOA IDR / ODR | `0x00004C04` / `0x00000000` | PA7/PA8/PA9/PA15 입력 읽기 LOW, SD 출력 지령 LOW |

대기 상태 읽기 로그: [idle_readback_hotplug.log](gdt_stop_fix_20261014/idle_readback_hotplug.log).
첫 읽기에 사용한 `mode=HOT`은 CLI에서 지원하지 않아 Normal 연결로 처리되었으며,
그 읽기 값은 판정에 사용하지 않았다. Reset/Run 후 정확한 `mode=HotPlug`로 재확인했다.
이 확인은 일반 STOP의 200 us 구간을 실측한 것이 아니며, 출력 ON/OFF 시험은 실행하지 않았다.

현장에서는 정지 순간의 PA7, SD, GDT 1차 차동전압 및 IRFP460 VGS를 비교한다.
PA7 LOW 이후 주기 경계에서 GDT 구동 펄스가 끝나고, 약 200 us의 클램프 구간 뒤
SD가 LOW가 되는지 확인한다. 클램프 해제 때의 추가 펄스도 확인해야 한다.
고전압부에는 정격에 맞는 차동 프로브를 사용한다.
