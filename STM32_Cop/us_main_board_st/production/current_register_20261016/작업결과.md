# 40004 실측 전류 프로토콜 변경 (2026-10-16)

- 40004 / PDU `0x0003`: 기존 Sweep 주파수를 `MEASURED_CURRENT`로 교체.
- FC03, 수량 1, unsigned 16-bit, 전류(A) ×100. 예: 523 = 5.23 A.
- 측정원: `ADC_Control_GetCurrentCentiAmp()`, PA6 CT 입력 소비전류.
  LCD와 동일한 1초 평균 RMS이며 200 ms마다 갱신한다.
- RUN/Sweep/Lock과 관계없이 최근 측정값을 반환한다. 정지 시 강제 0 처리를
  하지 않으므로 정지 직후 평균값 또는 대기 소비전류가 읽힐 수 있다.
- FC06/FC10 쓰기는 기존 읽기 전용 정책에 따라 Exception `0x02`로 거부한다.
- 40002 출력 지령 읽기/쓰기 및 제어 로직은 유지한다.
- Slave ID=1 읽기 요청: `01 03 00 03 00 01 74 0A`.
- 5.23 A 응답: `01 03 02 02 0B F8 E3`.

## 검증 및 배포

- Release Build 성공: `release_build.log`.
- `test_host` 8개 스크립트 전체 통과: `test_host.log`.
  기본 로직 37개 통과, Modbus 주소/전류 연결/읽기 전용/기존 출력 지령 계약과
  예제 CRC 확인 포함. 호스트 검사는 소스 계약 및 계산 검사이며 실기 시험은 아니다.
- UPDATE HEX checksum/주소 범위와 Release BIN 일치 확인. 설정 Page
  `0x0800F800`은 포함하지 않는다.
- 빌드 시 RWX LOAD segment 경고가 있으며 이전 빌드 로그에도 존재한다.
- 최초 빌드의 objcopy PATH 오류는 설치된 ARM 도구 경로를 빌드 프로세스의
  PATH에 추가하여 해결했다.
- PLC 가이드를 v1.4로 개정하고 관련 Markdown/Word 설명서를 갱신했다.
  python-docx가 설치되지 않아 기존 `tools/generate_field_update_package.py`의
  표준 라이브러리 DOCX 생성기를 사용했다. ZIP/XML 및 전류 사양 포함을 확인했다.
- 변경 전 소스, 안내서와 UPDATE HEX는 `before`에 보관했다.
- 현장 업데이트 파일: `../US_MAIN_BOARD_UPDATE_V1.2.0.hex`.
- SHA-256: `ED16BB2F3394DE27E77D2CDD18A39208AD8C3394C72A8DFD7E37173A206E02FF`.
- 보드 업로드, Writing/Verify/Reset/Run 및 PLC 실기 통신 시험은 수행하지 않았다.

## 적용 후 확인

1. 초음파 출력을 정지하고 UPDATE HEX를 사용한다. Full chip erase나 Factory
   HEX는 사용하지 않는다. Writing 후 Verify와 Reset/Run을 확인한다.
2. FC03으로 40004를 읽고 수신값 ÷100.0이 LCD 전류와 일치하는지 확인한다.
3. 기존 40002 출력 지령 읽기/쓰기 및 RUN/STOP 동작을 확인한다.
4. 기존 PLC에서 40004를 주파수로 해석했다면 전류로 수정한다. Sweep 순간
   주파수는 40001(`0x0000`)에서 읽는다.
