# 현장 노트북 개발환경 준비

## 목적

현장에서 Firmware를 다시 수정해야 할 때 VSCode와 Codex로 소스를 편집하고,
Release Build, Host Test, ST-LINK 업데이트까지 수행하기 위한 준비사항이다.

## 노트북에 필요한 프로그램

1. VSCode와 Codex
2. STM32CubeCLT 1.19.0 이상
   - ARM GNU Toolchain
   - CMake
   - Ninja
   - STM32CubeProgrammer CLI
3. STM32CubeProgrammer GUI
4. Python 3 (`Add Python to PATH` 선택)
5. STM32CubeG4 Firmware Package v1.6.2

STM32CubeG4 Package의 기본 위치는 다음과 같다.

```text
C:\Users\사용자명\STM32Cube\Repository\STM32Cube_FW_G4_V1.6.2
```

## 가져갈 파일

`US_MAIN_BOARD_DEVELOPMENT_SOURCE_2026-10-08.zip` 전체를 노트북으로 복사한다.
현재 작업내용은 GitHub에 모두 반영되지 않았으므로 현장에서 단순 `git clone`만
사용하지 않는다.

## 처음 실행하는 순서

1. ZIP을 `C:\STM32\us_main_board_st`처럼 짧은 로컬 경로에 압축 해제한다.
2. VSCode에서 압축을 해제한 폴더 전체를 연다.
3. Codex에게 먼저 프로젝트 구조와 `AGENTS.md` 지침을 확인하도록 요청한다.
4. 코드 수정 전 `production`의 Update HEX를 별도로 백업한다.
5. 수정 후 프로젝트 루트의 `build_release.bat`를 더블클릭한다.
6. `[PASS] Release Build와 전체 Host Test가 완료되었습니다.`를 확인한다.
7. 새 HEX가 `production` 폴더에 생성되었는지 시간과 크기를 확인한다.
8. 보드 출력을 정지하고 `production\program_update.bat`로 업데이트한다.
9. Writing, Verify, Reset/Run 성공 후 실제 부하에서 동작을 확인한다.

## 중요한 파일 구분

```text
US_MAIN_BOARD_UPDATE_V1.2.0.hex
  기존 주파수, Sweep, 운전시간과 통신 설정을 유지하는 현장 업데이트용

US_MAIN_BOARD_FACTORY_V1.2.0.hex
  출하 기본값과 Option Byte를 사용하는 최초 생산/전체 초기화용
```

현장에서 Firmware만 변경할 때에는 Update HEX를 사용한다. Full chip erase와
Factory HEX를 사용하면 저장된 사용자 설정이 초기화될 수 있다.

## 현장 작업 권장 순서

```text
현재 HEX 백업
→ 소스 수정
→ build_release.bat
→ 전체 Test PASS 확인
→ Update HEX로 Writing/Verify
→ 2 A, 3 A, 5 A 운전 확인
→ Auto-Tuning 확인
→ 변경 내용과 시험 결과 기록
```
