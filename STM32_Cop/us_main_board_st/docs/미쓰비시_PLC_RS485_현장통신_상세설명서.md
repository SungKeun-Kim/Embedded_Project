# 미쓰비시 PLC ↔ MCU RS485 현장 통신 상세 설명서

작성일: 2026-10-16 / 버전: 1.0 / 대상: STM32 초음파 제어 보드 현재 작업 소스

이 문서는 현장 담당자가 연결 확인부터 반복 읽기, 출력 쓰기, 통신 운전 및 외부 REMOTE 접점 운전까지 순서대로 시험하기 위한 설명서입니다. PLC 제조사는 미쓰비시이며 CPU·통신 모듈 모델, 실제 송수신 기록, 보드에 설치된 펌웨어는 아직 확인되지 않았습니다. 아래 명령은 소스로 확인했으며 실제 PLC/보드 시험 결과는 아닙니다.

## 1. 가장 먼저 확인할 세 가지

**첫째, 별도의 연결 시작 명령은 없습니다.** RS485 Modbus RTU는 PLC가 요청하면 MCU가 응답합니다. FC03 읽기 요청에 정상 응답이 오면 그 요청에 대한 통신이 성공한 것입니다. 한 번 읽었다고 MCU가 이후 상태를 자동으로 계속 전송하지 않습니다. 계속 감시하려면 PLC가 읽기 요청을 반복해야 합니다.

**둘째, 통신 성공과 출력 운전은 다릅니다.** 읽기에 성공해도 LCD가 485 COMM으로 바뀌지 않을 수 있습니다. 485 COMM은 Local Lock을 설정한 통신 제어 준비 상태이고, 현재 응답이 계속 오고 있다는 증거는 아닙니다. Lock ON을 쓴 것만으로 출력이 켜지지도 않습니다.

**셋째, 외부 REMOTE 접점 운전과 RS485 운전은 제어권이 다릅니다.** 다음 표에서 원하는 운전 방식을 먼저 선택합니다.

| 원하는 사용 방법 | Local Lock | 출력 ON/OFF 담당 | 출력 크기 담당 | 설명서 위치 |
| --- | --- | --- | --- | --- |
| 통신으로 상태만 읽기 | 변경 불필요 | 기존 운전 방식 | 기존 운전 방식 | 3~5절 |
| 통신하면서 외부 REMOTE 접점으로 운전 | OFF=0 | 외부 REMOTE 접점 | 보드 가변저항 | 6절 |
| PLC가 통신 명령으로 출력값과 운전 제어 | ON=0xFF00 | RS485 RUN 명령 | PLC 출력값. 가변저항 조작 시 인계 가능 | 7절 |

두 운전 방식 모두 보드 RUN_SW는 OFF로 두고, 설명서의 시험은 LCD 메인화면에서 시작합니다. 읽기 자체에는 Lock ON이 필요하지 않습니다.

**현재 코드에서는 'PLC 출력값을 계속 유지하면서 외부 REMOTE 접점으로 직접 ON/OFF'하는 혼합 운전을 지원하지 않습니다.** 출력 쓰기는 Lock ON을 요구하고, Lock ON이면 외부 REMOTE를 무시합니다. Lock을 해제하면 출력값도 보드 가변저항 기준으로 돌아갑니다. PLC 출력값을 유지하면서 PLC에서 받은 외부 운전 신호를 사용하려면 PLC가 그 신호를 보고 RS485 RUN ON/OFF를 보내는 방식으로 구성해야 합니다.

## 2. 시험 준비와 주소 입력

### 2.1 통신 설정

| 항목 | 설정 |
| --- | --- |
| PLC 역할 | Modbus RTU Master |
| MCU 역할 | Modbus RTU Slave |
| Slave ID | 기본 1. 실제 보드에 저장된 주소와 일치시킬 것 |
| 속도 | 기본 9600 bps. 실제 보드 설정과 일치시킬 것 |
| 데이터 / 패리티 / 정지 비트 | 8 bit / Even / 1 bit, 즉 8-E-1 |
| 최초 시험 응답 대기 | 요청 전송 완료 후 500 ms를 초기값으로 사용 |
| 최초 반복 시험 간격 | 정상 응답 후 1초 대기하고 다음 요청 |
| 시험 대상 | 한 대의 보드, 한 대의 Master |

500 ms와 1초는 원인 구분을 위한 PLC 초기 설정값입니다. 통신이 안정되면 필요한 갱신 주기에 맞춰 읽기 간격을 줄이며, 기존 가이드의 권장 시작 주기는 100 ms 이상입니다. 이전 요청 처리 중에 다음 요청을 겹쳐 보내지 않습니다.

RS485 옵션보드가 MCU에서 감지되어야 응답합니다. 연결선만 꽂혀 있고 옵션보드 감지가 되지 않으면 읽기도 무응답입니다. CPU·통신 모듈별 배선도에 따라 2선식 RS485와 신호 기준선을 연결하고, 종단 설정은 실제 배선 구성에 맞춥니다. A/B와 SDA/SDB/RDA/RDB 이름만 보고 단자를 임의로 대응시키지 않습니다.

처음에는 출력을 정지하고 외부 REMOTE도 OFF로 둡니다. PLC의 별도 자동 운전 로직이 시험 중 ON 명령을 보내지 않는지 확인합니다. PC 통신 도구로 비교 시험할 때는 PLC의 요청 전송을 중지해 두 Master가 동시에 요청하지 않게 합니다.

### 2.2 주소·숫자 표기

이 문서의 주소는 **PDU 0-based 주소**입니다. 예를 들어 출력 주소는 0x0001=10진수 1입니다. PLC 기능이 40001 방식 표기를 요구할 때는 40002에 해당합니다. 실제 프레임에 숫자 40002를 넣는다는 뜻은 아닙니다.

| 기능 | PDU 주소 | 10진수 주소 | 40001 방식 | 읽기/쓰기 |
| --- | --- | --- | --- | --- |
| 출력 설정값 | 0x0001 | 1 | 40002 | FC03/FC06, 0~500 |
| Local Lock | 0x0004 | 4 | 40005 | FC03/FC06, 0 또는 0xFF00 |
| RUN 상태/명령 | 0x0005 | 5 | 40006 | FC03/FC06, 0 또는 0xFF00 |
| 외부 REMOTE 입력 상태 | 0x0006 | 6 | 40007 | FC03 읽기 전용 |
| 에러 상태/Reset | 0x0008 | 8 | 40009 | FC03, 정지 중 FC06으로 0xFF00 Reset |
| 에러 코드 | 0x0009 | 9 | 40010 | FC03 읽기 전용 |
| 물리 RUN_SW 상태 | 0x000A | 10 | 40011 | FC03 읽기 전용 |
| 통신 제어 가능 상태 | 0x000B | 11 | 40012 | FC03 읽기 전용 |

Lock과 RUN의 ON 값은 0xFF00=65280입니다. 숫자 1을 쓰면 거부됩니다. signed 16-bit 화면에서 -256으로 보이더라도 16진수 패턴이 FF00이면 같은 값입니다. 이 보드의 ON/OFF는 **FC06 Holding Register 쓰기**이며 FC05 Coil 쓰기가 아닙니다.

## 3. 첫 연결 시험 — 이 명령 하나부터 보내기

### 3.1 PLC 통신 기능에 입력할 값

| 입력 항목 | 값 |
| --- | --- |
| Slave ID | 1 — 보드 주소가 1인 경우 |
| Function | FC03, Read Holding Registers |
| 시작 주소 | 0x0010 = 10진수 16 = 40017 방식 |
| 읽을 수량 | 3 registers |
| 수신 저장 영역 예 | D200~D202, 실제 빈 영역으로 지정 |

이 요청은 통신 설정 3개를 읽으므로 운전 상태를 변경하지 않습니다. 기본 설정 보드의 정상 데이터는 D200=1, D201=0, D202=1입니다. 순서대로 Slave ID, Baud index, Parity입니다. 실제 저장 설정에 따라 ID와 Baud index는 달라집니다.

Baud index 0/1/2/3/4는 9600/19200/38400/57600/115200 bps를 뜻합니다. Parity=1은 Even입니다. 이 읽기는 이미 통신 조건이 맞아야 성공하므로 속도를 자동 탐색하는 명령은 아닙니다.

### 3.2 실제 선로에서 보이는 HEX 예

아래는 Slave ID 1 기준이며 마지막 2바이트는 CRC입니다. PLC의 Modbus 전용 기능을 사용하면 보통 Slave/Function/주소/수량을 입력하고 프레임 구성은 그 기능이 담당합니다. 아래 전체 HEX를 데이터 레지스터에 중복해서 넣지 마십시오. 원시 시리얼 전송을 직접 구현하거나 통신 로그를 비교할 때 전체 HEX를 사용합니다.

| 방향 | 전체 RTU 프레임 |
| --- | --- |
| PLC → MCU 요청 | 01 03 00 10 00 03 04 0E |
| MCU → PLC 정상 응답, 기본 설정 | 01 03 06 00 01 00 00 00 01 DD 75 |

응답의 06은 오류 코드가 아니라 데이터 길이 6바이트입니다. 00 01 / 00 00 / 00 01이 16-bit 값 3개입니다. 정상 응답은 총 11바이트입니다.

### 3.3 처음 한 번 성공한 뒤 할 일

1. 정상 응답을 검사하고 수신 성공 횟수를 1 증가시킵니다.
2. 해당 PLC 명령의 매뉴얼에 따라 실행 요청·완료 처리를 정리합니다.
3. 1초 후 같은 읽기를 다시 실행합니다.
4. 이 과정을 10회 반복하여 송신 횟수와 정상 수신 횟수가 함께 증가하는지 확인합니다.
5. 10회 모두 성공하면 4절의 현재 출력 읽기로 이동합니다. 실패하면 9절에서 실패 위치를 구분합니다.

MCU는 요청 없이 상태를 자동 송신하지 않습니다. 첫 응답만 받고 더 이상 요청하지 않았다면 이후 수신이 없는 것은 정상입니다. LCD가 변하지 않는다는 이유만으로 무응답으로 판정하지 말고 PLC의 실제 수신 데이터 또는 통신 로그를 확인합니다.

## 4. 현재 출력값과 상태 읽기

### 4.1 출력값 한 개 읽기

FC03 / 시작 주소 0x0001 / 수량 1을 보냅니다. Slave ID 1의 전체 요청은 아래와 같습니다.

| 방향 | 전체 RTU 프레임 |
| --- | --- |
| 요청 | 01 03 00 01 00 01 D5 CA |
| 응답 예: 출력값 250 | 01 03 02 00 FA 38 07 |

00 FA=250입니다. 출력값은 설정 지령이며 실제 측정 전력 또는 운전 여부가 아닙니다. 정지 중에도 마지막 값 또는 가변저항에 따른 값이 남을 수 있습니다.

### 4.2 주요 상태를 한 번에 읽기

FC03 / 시작 주소 0x0000 / 수량 12를 보냅니다. Slave ID 1의 요청은 01 03 00 00 00 0C 45 CF입니다. 정상 응답은 Slave 01, Function 03, Byte count 18(16진수, 24바이트), 데이터 24바이트, CRC 2바이트로 총 29바이트입니다.

아래 D100~D111은 예시 저장 위치입니다. 실제 PLC에서 이미 쓰는 영역과 겹치지 않게 배치합니다.

| 수신 위치 예 | 보드 주소 | 의미 |
| --- | --- | --- |
| D100 | 0x0000 | 현재 주파수, 값 × 0.1 kHz |
| D101 | 0x0001 | 출력 설정값 0~500 |
| D102 | 0x0002 | LCD 현재 출력 표시 숫자(W 또는 %), 출력 표시가 없는 화면은 0 |
| D103 | 0x0003 | CT 실측 전류(A ×100), 예: 523 = 5.23 A |
| D104 | 0x0004 | Local Lock, 0 또는 FF00 |
| D105 | 0x0005 | RUN 상태, 0 또는 FF00 |
| D106 | 0x0006 | 외부 REMOTE 입력, 0 또는 FF00 |
| D107 | 0x0007 | 물리 SWEEP 스위치, 0 또는 FF00 |
| D108 | 0x0008 | 에러 상태, 0=정상, FF00=에러 |
| D109 | 0x0009 | 에러 코드, 0=없음, 1=Transducer, 2=Over current, 3=Output |
| D110 | 0x000A | 물리 RUN_SW, 0=OFF, FF00=ON |
| D111 | 0x000B | 통신 제어 가능, FF00=가능 |

통신 제어 가능 상태는 옵션보드 감지 + RUN_SW OFF + 메인화면 조건입니다. 에러 유무와 Lock ON 여부는 포함하지 않으므로 D108과 D104도 확인해야 합니다.

0x000F는 정의되지 않은 주소입니다. 상태와 통신 설정을 한 번에 읽으려고 0x0000~0x0012를 묶으면 잘못된 주소 오류가 발생합니다. 상태 블록과 통신 설정 블록은 나눠 요청합니다.

## 5. 계속 읽기 위한 PLC 처리 순서

아래는 모델에 관계없이 구현해야 하는 통신 처리 순서입니다. 실제 실행 접점, Busy, Done, Error의 이름과 해제 방법은 사용하는 CPU·모듈·명령 매뉴얼을 따릅니다.

| 단계 | PLC 처리 | 다음 단계 조건 |
| --- | --- | --- |
| 대기 | 이전 요청이 끝났는지 확인하고 새 읽기 파라미터 준비 | 통신 실행 가능 |
| 실행 | 읽기 명령 시작, 송신 횟수 증가 | 요청 시작 |
| 완료 대기 | 실행 중인 요청의 파라미터를 유지. 중복 요청 금지 | 정상 완료 또는 오류 완료 |
| 정상 완료 | 수신값 검사, 정상 수신 횟수와 마지막 성공 시각 갱신 | 정상 응답 확인 |
| 오류 완료 | Timeout/예외/PLC 오류를 구분해 기록 | 오류 처리 완료 |
| 다음 요청 준비 | 매뉴얼에 맞춰 요청·완료 상태를 처리하고 대기 간격 적용 | 다음 주기에 재실행 |

수신값이 계속 같다고 읽기가 멈춘 것은 아닙니다. 송신 횟수, 정상 수신 횟수, 마지막 수신 시각을 같이 확인합니다. 반대로 D 레지스터에 이전 값이 남아 있다고 현재 통신이 정상인 것도 아닙니다.

FX5에서 ADPRW를 사용하는 경우 공식 매뉴얼은 명령 완료 전까지 실행 접점을 OFF하지 않도록 설명합니다. 따라서 HMI 버튼을 한 번 눌렀다는 이유로 실제 통신 명령 구동 접점을 임의로 1스캔만 켜는 방식은 피하고, 해당 명령의 완료 처리 규칙에 맞춰 구성합니다. 다른 기종에는 이 규칙을 그대로 적용하지 말고 해당 매뉴얼을 확인합니다. [미쓰비시 FX5 공식 매뉴얼, 인쇄 페이지 42~43](https://dl.mitsubishielectric.com/dl/fa/document/manual/plcf/jy997d56101/jy997d56101h.pdf).

읽기 오류 시 최초 시험은 기록 후 중단하고 원인을 확인합니다. 자동 재시도를 구성한다면 한도를 정합니다. 특히 RUN ON 쓰기가 Timeout이면 MCU가 실제로 실행했지만 응답만 유실되었을 수도 있으므로, 무조건 RUN ON을 반복하거나 정지했다고 판단하지 말고 통신 복구 후 상태를 먼저 읽습니다.

## 6. 통신 도중 외부 REMOTE 접점으로 ON/OFF

이 절의 REMOTE는 보드 PA10에 들어오는 물리 외부 입력입니다. RS485 RUN 명령과 구분합니다. **RS485 읽기는 계속하고, 운전 ON/OFF는 접점이 담당하는 방식입니다.**

### 6.1 준비 — Lock OFF 확인

1. 보드 RUN_SW를 OFF, LCD를 메인화면으로 둡니다.
2. 외부 REMOTE를 실제 OFF로 만듭니다. 4.2절 상태 읽기로 D106=0인지 확인합니다.
3. D104가 FF00이면 기존 통신 제어 상태입니다. 먼저 FC06 / 주소 0x0005 / 값 0으로 RUN OFF를 보내고, 상태 읽기로 D105=0을 확인합니다.
4. 이어 FC06 / 주소 0x0004 / 값 0으로 Lock OFF를 보냅니다.
5. 상태를 읽어 D104=0, D105=0, D106=0, D110=0, D108=0인지 확인합니다. 이미 Lock OFF였다면 해제 쓰기는 생략할 수 있습니다.
6. 이후 통신은 FC03 주기 읽기를 유지합니다. 이 모드에서 Lock ON 또는 RUN ON을 보내지 않습니다.

Lock 해제 프레임은 01 06 00 04 00 00 C8 0B입니다. 정상 FC06 응답은 같은 프레임입니다. REMOTE가 켜진 채 Lock을 해제하면 다시 운전할 수 있으므로 순서를 지킵니다.

### 6.2 REMOTE ON

1. 설비의 정상 운전 조건을 확인한 뒤 외부 REMOTE 접점을 ON으로 합니다. 펌웨어 입력 기준은 Active LOW입니다. 실제 접점/전압 배선은 보드 회로에 맞춥니다.
2. MCU가 입력을 디바운스한 뒤 운전을 시작합니다.
3. PLC는 같은 FC03 읽기를 계속합니다. 별도 연결 명령이나 RUN ON 쓰기는 필요하지 않습니다.
4. D106=FF00, D105=FF00, D104=0, D108=0인지 확인합니다.
5. 정상 REMOTE 운전에서는 LCD에 RemoteON과 PL·주파수가 표시됩니다. 에러 또는 출력 시작 실패가 있으면 REMOTE가 ON이어도 RUN이 OFF일 수 있으므로 에러도 함께 확인합니다.

### 6.3 REMOTE OFF

1. 외부 REMOTE 접점을 OFF로 합니다.
2. MCU가 디바운스된 입력을 반영하여 운전을 정지합니다.
3. PLC 읽기는 계속합니다. D106=0, D105=0, D104=0인지 확인합니다.
4. LCD는 보통 STANDBY / K-SONICS 대기 화면으로 돌아갑니다. 출력 설정값 D101이 0이 아닐 수 있지만 운전 상태는 D105로 판단합니다.
5. 다음 ON/OFF도 같은 과정을 반복하며 Lock ON을 보내지 않습니다.

0x0006은 GPIO의 현재 입력을 바로 읽고, 운전 제어는 디바운스된 입력을 사용합니다. 따라서 접점을 바꾼 직후 한 번의 읽기에서 REMOTE와 RUN이 잠시 다를 수 있습니다. 잠시 뒤 다시 읽어 확인하고, 불일치가 계속되면 에러와 제어권을 점검합니다.

### 6.4 RUN과 REMOTE 두 개만 빠르게 읽는 명령

FC03 / 시작 주소 0x0005 / 수량 2를 사용합니다. 첫 번째 값은 RUN, 두 번째 값은 REMOTE입니다.

| 상황 | 전체 RTU 프레임 |
| --- | --- |
| 요청 | 01 03 00 05 00 02 D4 0A |
| 정상 대기 응답, RUN OFF / REMOTE OFF | 01 03 04 00 00 00 00 FA 33 |
| 정상 접점 운전 응답, RUN ON / REMOTE ON | 01 03 04 FF 00 FF 00 8B D7 |

RUN=0, REMOTE=FF00이면 에러·Lock·RUN_SW·화면 상태를 함께 확인합니다. Lock=FF00이면 물리 REMOTE가 무시되는 상태입니다.

이 방식의 출력 크기는 보드 가변저항으로 정합니다. RS485 출력 쓰기는 Lock OFF에서 거부됩니다. 또한 REMOTE가 ON인 상태에서 RS485 RUN OFF를 보내면 일시 정지 후 REMOTE 제어에 의해 다시 운전할 수 있으므로, 접점 운전을 정지할 때는 REMOTE 접점을 OFF로 하고 RUN 상태를 확인합니다.

## 7. RS485 명령으로 출력값 설정 및 ON/OFF

이 절은 PLC가 외부 접점 대신 RUN 명령까지 직접 보내는 방식입니다. 통신 제어 중 물리 REMOTE ON/OFF는 운전에 반영되지 않습니다.

### 7.1 제어권 확보

1. 외부 REMOTE OFF, 보드 RUN_SW OFF, LCD 메인화면에서 시작합니다.
2. 상태 읽기로 RUN_SW=0, 통신 제어 가능=FF00, 에러=0을 확인합니다.
3. FC06 / 주소 0x0004 / 값 0xFF00을 보냅니다. 프레임은 01 06 00 04 FF 00 89 FB입니다.
4. 정상 응답 후 상태를 읽어 Lock=FF00인지 확인합니다. OFF→ON으로 처음 전환될 때 기존 출력을 정지하고 현재 가변저항 값을 출력 지령으로 인계합니다.
5. 이미 Lock ON 상태였다면 같은 Lock ON 쓰기는 정지를 보장하지 않습니다. RUN이 ON이면 주소 0x0005에 0을 보내고 RUN=0을 확인합니다.

이때 LCD의 485 COMM / K-SONICS는 통신 제어 준비 상태를 뜻합니다. 아직 운전 ON이 아닙니다.

### 7.2 출력 설정값 쓰고 다시 읽기

1. 예를 들어 출력값 250을 쓰려면 FC06 / 주소 0x0001 / 값 250(0x00FA)을 보냅니다. 프레임은 01 06 00 01 00 FA 58 49입니다.
2. 같은 프레임의 정상 쓰기 응답을 확인합니다.
3. FC03 / 주소 0x0001 / 수량 1로 다시 읽어 250인지 확인합니다.
4. 값 불일치나 오류면 RUN ON 단계로 넘어가지 않습니다. 가변저항 조작으로 값이 바뀌었는지도 확인합니다.

250은 설명용 예이며 설비에 사용할 적정값을 지정하는 것은 아닙니다. 정지 중 LCD는 PL 숫자를 숨기므로 PLC 다시 읽기로 확인합니다.

### 7.3 RUN ON

1. 운전 조건을 확인한 뒤 FC06 / 주소 0x0005 / 값 0xFF00을 보냅니다. 프레임은 01 06 00 05 FF 00 D8 3B입니다.
2. 정상 쓰기 응답을 확인합니다.
3. 상태를 다시 읽어 Lock=FF00, RUN=FF00, 에러=0을 확인합니다. 쓰기 응답만으로 출력 시작 성공까지 확정하지 않습니다.
4. LCD에 485 ON과 PL·설정 주파수가 표시됩니다. 출력값 250이라면 일반 퍼센트 화면은 PL: 53%입니다.
5. 운전 중 FC03 상태 읽기를 계속합니다. 크기를 바꾸려면 출력 주소에 새 값만 쓰고 다시 읽습니다. 매번 RUN ON을 다시 보낼 필요는 없습니다.

### 7.4 RUN OFF와 다음 운전

1. FC06 / 주소 0x0005 / 값 0을 보냅니다. 프레임은 01 06 00 05 00 00 99 CB입니다.
2. 정상 응답을 확인하고 FC03 상태 읽기로 RUN=0인지 확인합니다.
3. Lock은 FF00으로 유지됩니다. LCD는 485 COMM / K-SONICS로 돌아갑니다.
4. 다시 통신 운전할 때는 Lock·제어 가능·에러·출력값을 재확인한 후 RUN ON을 보냅니다. 상태가 유지되고 있다면 Lock을 반복 해제·설정할 필요는 없습니다.

출력값 0은 RUN OFF가 아닙니다. 운전 중 값 0은 최소 PA7 PWM 5%와 LCD PL: 5%에 해당합니다. 통신 운전은 보드 M/S 타이머로 자동 종료되지 않으므로 필요한 시점에 PLC가 RUN OFF를 보내야 합니다.

### 7.5 PLC 출력값과 LCD 관계

| PLC 설정값 | 운전 중 PA7 PWM 지령 | 일반 LCD 퍼센트 표시 |
| --- | --- | --- |
| 0 | 5.0% | 5% |
| 100 | 24.0% | 24% |
| 250 | 52.5% | 53% |
| 500 | 100.0% | 100% |

W 표시 모드라면 위 LCD 정수 퍼센트에 보드 설정 최대 W를 곱합니다. 최대 1000W일 때 설정값 0은 50W, 250은 530W로 표시됩니다. 실제 전력 계측값이 아닙니다. 2026-10-16 변경본부터 40004(`0x0003`)에서 PA6 CT 실측 입력 소비전류를 A ×100으로 읽습니다. LCD와 동일한 1초 평균 RMS이며 200 ms마다 갱신합니다. 정지 중에도 측정값을 반환합니다. 실제 전력 측정 레지스터는 제공하지 않습니다.

## 8. 통신 운전과 접점 운전 사이 전환

### 8.1 통신 운전 → 외부 REMOTE 운전

1. 외부 REMOTE를 OFF로 하고 입력 상태 0을 확인합니다.
2. 통신 RUN OFF를 보내고 RUN=0을 확인합니다.
3. Lock OFF를 보내고 Lock=0, RUN=0을 확인합니다.
4. 보드 가변저항이 원하는 출력 위치인지 확인합니다. Lock 해제 시 PLC 설정값을 그대로 유지하지 않고 가변저항 기준으로 돌아갑니다.
5. 통신 주기 읽기는 그대로 유지한 채 외부 REMOTE를 ON/OFF합니다.

### 8.2 외부 REMOTE 운전 → 통신 운전

1. 외부 REMOTE를 OFF로 하고 RUN=0을 확인합니다.
2. RUN_SW OFF, 메인화면, 통신 제어 가능, 에러 없음을 확인합니다.
3. Lock ON을 보내고 Lock=FF00, RUN=0을 확인합니다.
4. 원하는 출력값을 쓰고 다시 읽어 확인합니다.
5. 통신 RUN ON을 보내고 실제 RUN 상태를 확인합니다.

Lock ON 중 작업자가 가변저항을 기준점에서 약 5% 이상 움직이면 출력 크기가 수동으로 인계될 수 있습니다. 이후 작은 조작도 반영되고, PLC가 다시 쓰면 PLC 지령이 우선됩니다. Lock 이름만 보고 모든 보드 조작이 잠긴다고 해석하지 마십시오.

## 9. '한 번 보내고 반응 없음' 점검 순서

현재 현장의 송수신 기록이 없으므로 원인은 미확정입니다. 아래 순서로 실패 지점을 좁힙니다. 시험은 3절의 읽기 명령만으로 시작합니다.

### 9.1 PLC 송신 자체가 한 번뿐인가?

1. PLC의 실제 송신 횟수나 통신 모니터를 봅니다. 프로그램의 요청 비트만 확인하지 않습니다.
2. 첫 요청 후 실행 조건이 다시 만들어지는지 확인합니다. 최초 스캔 전용 조건 또는 한 번만 눌리는 버튼에만 연결되어 있으면 한 번만 실행될 수 있습니다.
3. 첫 완료 후 상태 번호가 다음 단계로 이동하는지, 완료/오류 처리 뒤 다음 요청으로 복귀하는지 확인합니다.
4. Busy가 계속 남아 있으면 완료/오류 비트와 Timeout 설정을 확인합니다. Busy 중에 무작정 새 요청을 넣지 않습니다.
5. 모델별 통신 명령의 실행 유지 및 재실행 조건을 확인합니다. FX5 ADPRW의 경우 5절의 완료 전 접점 유지 조건을 참고합니다.

### 9.2 PLC는 계속 보내는데 MCU 응답이 없는가?

1. Slave ID가 보드의 실제 ID인지 확인합니다. 주소 0의 Broadcast 쓰기는 실행되더라도 응답하지 않으며 Broadcast 읽기도 응답하지 않습니다.
2. 8-E-1, 속도, RS485 옵션보드 감지, 데이터선 극성, 송수신 방향 전환을 확인합니다. RS485 송신 후 PLC 측이 수신 가능 상태로 돌아가야 응답을 받을 수 있습니다.
3. 3.2절 요청과 실제 선로의 바이트를 비교합니다. ASCII 문자 '01 03...'를 보내는 것이 아니라 해당 값의 바이너리 바이트를 전송해야 합니다. RTU 프레임에 CR/LF를 덧붙이지 않습니다.
4. CRC는 하위 바이트가 먼저입니다. 주소·값·Slave ID를 바꾸면 CRC도 다시 계산합니다. Modbus 기능이 CRC를 붙이는데 사용자 데이터에 CRC를 한 번 더 붙인 것은 아닌지 확인합니다.
5. 최초 시험은 한 요청 전체를 연속 전송하고 응답 후 1초를 기다립니다. 프레임을 바이트별로 긴 간격을 두고 나누거나, 이전 응답 전에 새 요청을 겹치지 않습니다.
6. MCU는 프레임 길이·CRC·주소·수신 타이밍이 맞지 않는 요청을 응답 없이 버릴 수 있습니다. 코드상 9600 bps의 t1.5는 약 1.719 ms, t3.5는 약 4.011 ms입니다. 이는 프레임 구분 시간이며 운전 정지 Timeout과 다릅니다.
7. 첫 정상 응답 후부터 실패한다면 첫 응답과 두 번째 요청 사이 간격, PLC 명령 상태, 수신 길이 처리, 송수신 방향 전환을 우선 비교합니다. 이 증상만으로 PLC 또는 MCU 결함을 단정하지 않습니다.

### 9.3 MCU 응답은 있는데 PLC가 실패라고 하는가?

1. 정상 응답 길이를 확인합니다. FC03은 읽기 수량 N에 대해 5+2N 바이트이고, FC06 정상 응답은 8바이트입니다.
2. 예외 응답은 5바이트입니다. 고정 길이 8/11/29바이트만 기다리는 원시 수신 프로그램은 예외 응답을 받고도 Timeout으로 오인할 수 있습니다.
3. 기능 코드에 0x80이 더해진 응답을 확인합니다. FC03 오류는 0x83, FC06 오류는 0x86입니다.
4. 변환기나 포트의 송신 Echo를 실제 응답으로 오인하지 않았는지 확인합니다. FC06은 정상 응답 자체가 요청과 같으므로 FC03 읽기 시험을 함께 사용하면 구분에 도움이 됩니다.

| 예외 코드 | 의미 | 확인 사항 |
| --- | --- | --- |
| 0x01 | 지원하지 않는 Function | 이 보드는 FC03/FC06/FC10 지원. FC04/FC05 등을 사용했는지 확인 |
| 0x02 | 잘못된 주소 또는 읽기 전용 주소 쓰기 | 0-based 주소, 0x000F 포함 여부, REMOTE 주소 쓰기 여부 |
| 0x03 | 값 또는 현재 제어 조건 부적합 | Lock, RUN_SW, 메인화면, ON=FF00, 출력 0~500, 에러 여부 |
| 0x04 | 명령 실행 실패 | 상태와 에러를 다시 읽고 원인 확인 |

Slave ID 1에서 FC06 조건 오류 예시는 01 86 03 02 61입니다. 이 응답이 오면 MCU까지 요청이 전달되고 MCU가 거부 사유를 회신한 것이므로, 배선 단절과 구분해서 조건을 확인합니다.

### 9.4 통신 응답은 정상인데 출력 또는 화면 반응이 없는가?

- 읽기만 보냈다면 화면이 485 COMM으로 바뀌지 않는 것이 정상일 수 있습니다. 수신 데이터로 통신을 판단합니다.
- Lock ON만 보냈다면 출력이 켜지지 않는 것이 정상입니다. 통신 운전은 별도 RUN ON 명령이 필요합니다.
- 출력값만 썼다면 출력 크기 설정만 바뀝니다. 정지 중 PL 숫자를 숨기므로 다시 읽기로 확인합니다.
- 외부 REMOTE 접점을 조작했는데 반응이 없다면 Lock이 FF00인지 먼저 확인합니다. Lock ON에서는 REMOTE 상태는 읽히지만 운전을 제어하지 않습니다.
- RUN ON을 보냈다면 상태를 다시 읽어 에러, Lock, RUN_SW, 통신 제어 가능 상태를 확인합니다. 응답 성공과 실제 운전 시작을 구분합니다.

## 10. 통신 두절·에러·재접속 처리

현재 펌웨어에는 케이블 통신 두절만으로 출력을 자동 정지하는 통신 Timeout 기능이 없습니다. PLC의 응답 대기시간 500 ms가 지났다고 MCU가 자동 정지하는 것은 아닙니다. 통신 불량은 '현재 운전 상태 확인 불가'로 처리하고 설비가 정한 정지 절차를 적용합니다. RS485 옵션보드 자체의 감지가 사라지는 조건과 케이블 단선은 다릅니다.

재접속하면 3절 읽기로 통신을 확인한 뒤 전체 상태를 먼저 읽습니다. 이전 Lock과 RUN이 유지되고 있을 수 있으므로 부팅 초기 상태라고 가정하지 않습니다. 초기화된 순서로 다시 시작하려면 현장 운전 조건을 확인하고 RUN OFF 및 정지 확인을 거칩니다. 이미 Lock ON인 보드에 Lock ON을 다시 쓰는 것만으로 정지시키지 못합니다.

에러가 발생하면 에러 코드와 운전 상태를 먼저 기록합니다. 원인을 해결하고 정지 상태를 확인한 뒤 FC06 / 주소 0x0008 / 값 FF00으로 Reset을 요청합니다. 다시 읽어 에러=0인지 확인합니다. Reset만으로 자동 재운전하지 말고 운전 허용 조건을 재확인합니다.

| 번호 | 용도 | 요청 전체 HEX, CRC 포함 |
| --- | --- | --- |
| Q01 | 연결 확인: FC03, 주소 16, 수량 3 | 01 03 00 10 00 03 04 0E |
| Q02 | 출력 읽기: FC03, 주소 1, 수량 1 | 01 03 00 01 00 01 D5 CA |
| Q03 | 상태 읽기: FC03, 주소 0, 수량 12 | 01 03 00 00 00 0C 45 CF |
| Q04 | Lock ON: FC06, 주소 4, 값 FF00 | 01 06 00 04 FF 00 89 FB |
| Q05 | 출력값 250: FC06, 주소 1, 값 00FA | 01 06 00 01 00 FA 58 49 |
| Q06 | 통신 RUN ON: FC06, 주소 5, 값 FF00 | 01 06 00 05 FF 00 D8 3B |
| Q07 | 통신 RUN OFF: FC06, 주소 5, 값 0 | 01 06 00 05 00 00 99 CB |
| Q08 | Lock OFF: FC06, 주소 4, 값 0 | 01 06 00 04 00 00 C8 0B |
| Q09 | RUN/REMOTE 읽기: FC03, 주소 5, 수량 2 | 01 03 00 05 00 02 D4 0A |
| Q10 | Lock 읽기: FC03, 주소 4, 수량 1 | 01 03 00 04 00 01 C5 CB |
| Q11 | 에러/코드/RUN_SW/제어가능: FC03, 주소 8, 수량 4 | 01 03 00 08 00 04 C5 CB |

외부 REMOTE 접점 시험 순서: Q01 반복 성공 → Q03 상태 확인 → REMOTE OFF → 필요한 경우 Q07로 정지 확인 → 필요한 경우 Q08로 Lock 해제 확인 → Q03 또는 Q09 반복 읽기 → 물리 REMOTE ON → 상태 확인 → 물리 REMOTE OFF → 상태 확인.

통신 운전 시험 순서: Q01 반복 성공 → Q03 상태 확인 → Q04 → Lock/RUN 확인 및 필요 시 Q07 정지 → Q05 → Q02로 값 확인 → Q06 → Q03 주기 감시 → Q07 → 정지 확인. Local로 복귀할 때만 REMOTE OFF 확인 후 Q08을 실행합니다.

Q01~Q11은 외우기 위한 문서 번호이며 전송하는 데이터가 아닙니다. Slave ID가 1이 아니면 첫 바이트와 CRC를 바꿔야 합니다. 주소·값은 상위 바이트부터, CRC는 하위 바이트부터 전송합니다.

## 12. 담당자가 남길 시험 기록과 확인 근거

| 기록 항목 | 현장 기입 내용 |
| --- | --- |
| PLC CPU / RS485 모듈 모델 | 명판의 정확한 모델명 |
| 보드 주소 / 속도 / 패리티 | 실제 설정 |
| 요청 내용 | Function, 시작 주소, 수량 또는 쓰기값, 송신 HEX |
| 응답 내용 | 수신 HEX 또는 Timeout, PLC 오류 코드 |
| 반복 시험 결과 | 송신 횟수 / 정상 수신 횟수 / 마지막 성공 시각 |
| 운전 조건 | RUN_SW, REMOTE, LCD 화면, Lock, RUN, 에러 |
| 실패 시점 | 최초 요청부터 / 첫 성공 이후 / RUN ON 이후 등 |

이 기록이 있으면 PLC 재실행 조건 문제, 통신 프레임 문제, MCU 쓰기 조건 거부를 구분할 수 있습니다. 현재는 이 기록이 없으므로 특정 원인으로 확정하지 않습니다.

확인한 펌웨어: include/params.h, include/modbus_regs.h, src/modbus_regs.c, src/modbus_rtu.c, src/modbus_crc.c, src/menu.c, src/menu_screen.c, src/ultrasonic_ctrl.c, src/ultrasonic_pwm.c. Modbus 처리 조건, 제어권 전환, 원시 REMOTE 읽기와 디바운스된 운전 처리, LCD 표시를 대조했습니다.

미쓰비시 명령 동작 참고: [MELSEC iQ-F FX5 User's Manual — MODBUS Communication](https://dl.mitsubishielectric.com/dl/fa/document/manual/plcf/jy997d56101/jy997d56101h.pdf), Master 프로그램 및 작성 주의사항. FX5 설명은 해당 명령을 실제 사용하는 경우에만 적용합니다.

문서의 프레임 CRC는 계산 및 펌웨어 CRC 테이블과 대조했습니다. 이는 통신 예제의 데이터 검증이며 실제 장비 시험을 대신하지 않습니다. 이번 작업에서는 펌웨어를 수정하거나 업로드하지 않았습니다.
