# PLL 자동 튜닝·저장·보호 검토 및 1차 수정

> 이 문서는 1차 수정 당시의 기록이다. 이후 PWM 50% 고정, 반복 최소점 확인,
> 최소점+1 저장, 전체 시간 제한 제거를 반영했다.
> **현재 동작과 최신 검증 결과는 [초기 자동 튜닝 사양](./PLL_AUTOTUNE_SPEC.md)을 우선한다.**
> 아래 노브 목표 PWM, 61/70초 제한, 테스트 9개 설명은 당시 상태다.

이 문서는 **실물 시험 전 펌웨어 후보**에 대한 기록이다. 코드와 호스트 테스트를 검증했으며, 이번 작업에서 MCU에 기록하거나 실물 전류·파형·EEPROM을 읽지는 않았다. 운전 중 자동 위상 탐색은 기본적으로 비활성이다. 피드백 트랜스와 콘덴서 고장 방지가 입증된 출고 버전으로 취급하면 안 된다.

## 1. 확인된 실제 사용 조건

- 20 kHz급 진동자와 부스터만 연결한 무부하 전류는 보통 0.2 A 이내다.
- 알루미늄 공구혼까지 연결하면 약 0.4 A, 철 공구혼이면 약 0.5 A다. 이는 사용자 설명에 따른 **무부하 값**이며 압착 중 허용 전류가 아니다.
- 연속 작업은 보통 1.5~3 A, 프레스형 순간 작업은 압착 순간 최대 5.5 A까지 올라간다. 사용자 작업 상한은 5.5 A이며 앰프 자체의 최대 10 A와 구별한다. 진동부는 최대 2000 W이고 보통 1500 W로 사용한다. 이 전력값만으로 DC 입력전압이나 ADC 차단값을 역산하지 않는다.
- 공진 브릿지의 J1 신호가 F_B1으로 들어온다. INPUT1, TR15, 위상 조정 회로를 거쳐 LM565 입력으로 연결된다.
- PHASE2의 수동 10 kΩ 가변저항과 AD5280은 동시에 연결되어 사용된다. 따라서 AD5280 단독 저항 범위를 전체 위상 조정 범위로 해석하면 안 된다. 기존 도면의 PHASE2는 DIGIPOT_WB와 PHASE1_WB 사이에 있으므로 실제 결선과 SW3 상태까지 확인해야 합성 저항을 확정할 수 있다.
- 정상 정지 중에도 PLL을 유지하기 위한 미세 초음파 출력이 있다. 이 대기 동작은 유지한다.
- 출고 후 비슷한 주파수의 다른 혼을 장착할 수 있고, 작업 중 압력이 수시로 변한다.

수입 장비의 아날로그 곱셈기는 위상 검출 또는 전력 관련 연산에 사용되었을 가능성이 있지만, 회로와 IC 형번 없이 내부 알고리즘을 확정할 수 없다. 이번 전류 탐색 방식이 그 회로와 동등한 제어라고 가정하지 않는다.

## 2. 질문별 기존 코드 판정

| 질문 | 수정 전 확인 결과 |
|---|---|
| 3초 누르면 제대로 튜닝하는가? | PB7 A_TUNE 길게 누르기 경로는 있으나 3초 전용 계시가 아니다. 메인 반복 호출과 tick 공유에 의존한다. 탐색에서도 개선된 +1 위치를 다시 비교해 조기 종료할 수 있었다. |
| 저장이 되는가? | EEPROM 0x02에 코드, 0x03에 8비트 주파수를 기록한다. 하지만 완료 통지를 저장보다 먼저 보내고, 쓰기 시작의 4클록 제한이 인터럽트에 노출되며, 재확인·체크섬·전원 중단 대책이 없었다. |
| 전원을 다시 켜면 복원하는가? | 0xFF가 0x55이면 설정을 읽고 221~249 범위 검사 후 AD5280에 전송하는 경로가 있다. 실제 RDAC 값을 읽어 확인하지는 않았다. |
| 사용 중 온도 변화에 전류를 최소화하는가? | 전류를 재비교하지 않는다. 저장 주파수와 현재 주파수의 차이에 따라 저항 코드를 정하는 방식이었다. |
| 튜닝 중 보호되는가? | ATmega16A의 주기적 과전류 검사가 튜닝 중 중단되고, ATmega8의 오류 중단 코드는 주석 처리되어 있었다. |

작업 폴더의 `20261106_231218_68a6ec62/eeprom-after.bin` 백업에는 코드 **233**, 구형 주파수 바이트 **105**, 식별값 **0x55**가 있었다. 이 파일의 0x100~0x11F는 모두 0xFF였다. 과거 백업의 관찰이며 현재 장착된 MCU의 저장 상태를 증명하지 않는다.

수정 전 파일은 `.build/firmware_before_review_20261107_213911/`에 보관했다.

같은 ATmega8 백업의 `lfuse=0xFF`, `hfuse=0xC9`에서 BODEN은 미프로그램(저전압 리셋 비활성) 상태다. 현재 실물도 같은지는 재확인이 필요하다. 저전압에서의 EEPROM/CPU 오동작 대책과 관련되지만 이번 작업에서 퓨즈는 변경하지 않았다.

## 3. 이번에 구현한 동작

### 3.1 버튼과 출력 준비

1. A_TUNE(PB7)을 정지 상태에서 약 3초 유지하면 한 번만 요청한다. 버튼을 놓기 전에는 재요청하지 않는다. 16 MHz에서 100.8 ms 틱 31회를 사용하므로 대략 3.02~3.12초다.
2. 기존 출력 조절식으로 노브의 목표 PWM을 한 번 정한다. 100.8 ms마다 최대 3단계씩 접근해 갑작스러운 출력 상승을 피한다. 77에서 250까지면 준비 시간이 약 6초 추가될 수 있다.
3. 목표에 도달한 뒤 두 틱 유지하고 ATmega8에 탐색 시작을 보낸다. 탐색 중 출력 목표는 고정한다.
4. 출력 준비 중에도 두 MCU의 과전류 검사 경로를 사용한다.

‘3초’는 **시작 버튼 유지 시간**이다. 튜닝 완료 시간이 3초라는 뜻은 아니다. ATmega8 탐색은 약 61초 제한이고, ATmega16A는 시작 응답 약 2초 및 탐색 전체 약 70초 제한을 둔다.

### 3.2 전류 탐색

- 기존 코드 범위 221~249를 유지한다. 수동 가변저항을 포함한 실제 위상 범위를 넓히지 않는다.
- 각 코드 적용 시 AD5280에 쓰고 RDAC 값을 읽어 같은지 확인한다.
- 약 819 ms 안정 시간을 둔 뒤 약 164 ms 동안 ADC 32개를 수집한다.
- 32개 합계로 비교해 평균의 소수 정보를 정수 나눗셈으로 잃지 않는다.
- 첫 +1 위치에서 개선되었다면 그 위치를 기준으로 다음 위치를 측정하도록 탐색 순서를 수정했다.
- 양 끝에 도달한 최소값, 평탄하여 변화가 확인되지 않는 응답, 불안정한 샘플, 무계수, 시간 초과는 성공으로 저장하지 않는다.
- 마지막으로 선택한 코드를 다시 적용하고 전류를 재확인한 후, 그 상태의 16비트 주파수 계수를 저장한다.
- 실패하면 이전 저장 코드를 재적용하고 오류를 유지한다. 오류 후 자동 출력 재개는 하지 않는다.

이는 **현재 수동 설정 주변의 국소 최소점 탐색**이다. 여러 공진 모드 중 기계적으로 올바른 모드를 식별하는 기능은 아니다. 외부 압력이 없는 초기 튜닝 조건과 실제 출력 확인이 필요하다.

### 3.3 저장과 재기동

새 저장 영역은 다음과 같다. 업로드 알림 영역 0x1F8~0x1FF와 겹치지 않는다.

| 주소 | 용도 |
|---|---|
| 0x100~0x107 | 저장 슬롯 A |
| 0x108~0x10F | 저장 슬롯 B |
| 0x02, 0x03, 0xFF | 구형 펌웨어 호환 사본 |

각 8바이트 슬롯은 `유효 표시 / 버전 / 순번 / 저항 코드 / 주파수 하위 / 주파수 상위 / 코드 반전값 / CRC-8`이다.

- 이전 정상 슬롯을 남겨 두고 다른 슬롯에 쓴다.
- 각 바이트를 읽어 확인하며, 유효 표시는 마지막에 기록한다. 그 직전에도 중단·오류 여부를 확인한다.
- 유효한 새 슬롯을 전체 재검증한 뒤 완료를 알린다. 같은 설정이면 불필요한 재기록을 생략한다.
- EEPROM 쓰기 시작만 짧게 인터럽트로부터 보호한다. 컴파일된 명령에서 두 EECR 쓰기 사이가 4클록 이내인 것을 확인했다.
- 부팅 때 두 슬롯 중 최신 유효 값을 선택한다. 없으면 구형 0x02 설정을 범위 검사해 읽는다. 구형 주파수의 잃어버린 상위 바이트는 복원했다고 가정하지 않는다.
- 부팅 시 AD5280 쓰기와 읽기 확인을 수행한다. 실패하면 제어 오류를 반복 통지한다.
- 유효한 설정이 전혀 없으면 233을 대기·초기 튜닝 기준으로 쓰되, 튜닝 전에 정상 운전 명령을 받으면 오류 처리한다.

구형 호환 사본은 새 슬롯이 검증된 다음 갱신한다. 새 슬롯은 정상이어도 사본 갱신 중 전원 중단 시 구형 펌웨어로 복귀한 결과는 달라질 수 있다. 롤백 전에는 백업을 기준으로 설정을 확인해야 한다. 두 슬롯과 CRC는 모든 저전압·하드웨어 고장을 막는 수단이 아니므로 BOD/전원 강하 시험도 필요하다.

### 3.4 측정·통신·오류

- ATmega8 주파수 계수를 8비트에서 16비트로 바꿨다. 16 MHz와 1/8 분주가 맞다면 `발진 주파수[Hz] ≈ 계수 × 31.25`다. 20 kHz는 약 640이며, 실제 계시 오차는 교정해야 한다.
- INT1에서는 계수만 한다. ADC 대기와 중첩 인터럽트를 제거했다. ADC는 연속 변환하고 Timer0에서 최신 완료값을 수집한다.
- 공유 측정값에는 volatile 및 짧은 원자적 복사를 적용했다.
- ATmega16A ADC는 새 변환 완료를 확인하고 채널 변경 직후 첫 값을 버린다. 16 MHz에서 ADC 클록은 125 kHz로 바꿨다.
- I2C는 NACK에서 실패하고 시간 제한 후 빠져나온다. STOP이 완료되지 않는 경우도 실패한다.
- UART 하드웨어 오류가 있는 바이트는 명령으로 처리하지 않는다. 정지/오류 명령이 일반 명령에 덮이지 않도록 우선한다. 다만 기존 단일 바이트 프로토콜에 CRC·시퀀스·지속적인 연결 감시를 추가한 것은 아니다.
- ATmega16A는 튜닝 중에도 ADC와 과전류 검사를 한다. 튜닝 오류를 일반 완료로 바꾸던 처리를 제거했다.
- 오류 시 `SONIC_OUTPUT=0`, `OCR2=0`, 오류 출력과 정지 통지를 설정한다. 정상 정지의 `OCR2=77` 미세 출력은 유지한다. **실제 SD/HO/LO 차단은 SW3와 실물 회로에서 검증해야 한다.**

ATmega8의 기존 450, ATmega16A의 기존 500 ADC 문턱은 실제 암페어로 검증된 값이 아니다. 이번에 ATmega8의 미사용 문턱을 실제 보호 경로에 연결했으므로, 종전과 차단 시점이 달라질 수 있다. 변환 완료 처리도 달라졌으므로 센서 보정 없이 출고용 한계로 삼으면 안 된다. 16A의 5회 연속 판정은 명목 약 0.5초이며 빠른 하드웨어 차단을 대신하지 못한다.

## 4. 압력이 변하는 운전 중 튜닝

`pll_control_config.h`의 `PLL_RUNTIME_TRACKING_ENABLED`는 **0**이다. 수정 전의 저장 주파수 차이 기반 보정도 제거했으므로, 기본 빌드에서는 운전 중 저장된 위상 코드를 유지하고 LM565가 아날로그 추종을 한다.

시험용 구현은 다음과 같다.

1. 현재 위치 A에서 전류와 주파수를 측정한다.
2. 한 단계 옆 B를 측정한다.
3. A로 돌아가 다시 측정한다.
4. 앞뒤 A 측정이 충분히 같고 B의 전류가 작을 때만 B를 채택한다.
5. 저장 기준의 ±3코드와 221~249 안에서만 움직인다. 운전 중 결과는 EEPROM에 쓰지 않는다.

압력 변화로 A 값이 달라졌으면 그 비교는 버린다. 다만 **B를 측정하는 동안만 압력이 바뀌었다가 돌아오는 경우는 이 검사로도 구별할 수 없다.** DC 입력전류만으로 온도·압력·출력 진폭 변화를 완전히 분리할 수 없기 때문이다.

따라서 활성화 전에는 다음이 필요하다.

- 알려진 작업 상한 5.5 A와 앰프 정격 10 A를 바탕으로, 센서 오차와 정상 순간 피크의 지속시간을 포함해 차단 문턱/지연 및 허용 주파수 범위를 확정한다. 10 A까지 정상 운전을 허용하는 제어로 만들지 않는다.
- 출력 설정과 압력이 안정된 구간에만 탐색하도록 운전 조건 또는 별도 허가 신호를 정한다. 안정 구간이 없다면 전압·전류 위상 또는 브릿지 피드백에 대한 추가 측정이 필요하다.
- AD5280 한 단계가 실제 위상·출력·전류에 미치는 영향을 확인한다.
- 급격한 변화에는 탐색을 멈추고 LM565의 추종 및 보호를 우선한다.
- 설정에서 주파수 하한/상한을 지정하지 않고 운전 중 추적만 켜면 컴파일 오류가 나도록 했다. 현재 두 한계는 0(미확정)이다.

운전 중 코드의 컴파일은 **별도 복사본과 임의의 시험용 범위**로 확인했다. `.build/runtime_compile_only/` 산출물은 장비에 기록하면 안 된다.

프레스형은 압착 순간과 압착 유지 중 위상 탐색을 보류하고, 해제 후 압력이 없고 출력이 일정한 구간을 확인해 보정하는 방법이 우선 검토 대상이다. 연속 작업의 1.5~3 A 변화는 부하 변화일 수 있으므로 전류가 흔들린다는 이유만으로 위상을 이동시키지 않는다. 평균/분산 검사만으로 작업 상태를 확실히 알 수 없으므로 압착 신호나 충분한 독립 측정이 없는 현재 기본 빌드에서는 추적을 켜지 않았다.

## 5. 전류 분해능과 고장 원인 확인

회로도 부품은 ACS712ELCTR-20A-T다. 데이터시트상 감도는 명목 100 mV/A여서 0.2~0.5 A 변화는 센서 원출력에서 약 20~50 mV다. 5 V 기준 10비트 ADC의 한 단계는 약 4.88 mV이며, 실제 CURRENT에는 분압·다이오드·평활 회로가 추가된다.

따라서 평균을 내는 것은 도움이 되지만 센서 오프셋, 온도 드리프트, 다이오드 특성, 잡음과 ADC 기준전압 오차까지 제거하지는 못한다. `CURRENT` 전압과 ADC 값이 0 A, 약 0.2 A, 0.4 A, 0.5 A 및 압착 운전 전류에서 어떻게 달라지는지 측정해야 한다. 현재 0.5 ADC 단계에 해당하는 전류 비교 문턱과 샘플 안정 조건은 시험용 설정이다.

보정 기록은 아래처럼 두 MCU를 별도로 작성한다. 0 A/1.5 A/3 A/5.5 A를 포함하되, 큰 전류를 만들기 위해 혼을 무리하게 압착하지 않고 통제된 부하 시험 조건에서 확인한다. 평활 회로 때문에 피크에 대한 응답 지연도 함께 확인한다.

| 실제 DC 전류 | CURRENT 전압 | ATmega8 평균 ADC | ATmega16A ADC | 유지시간/조건 |
|---|---|---|---|---|
| 0 A | 미측정 | 미측정 | 미측정 | 센서 영점 |
| 무부하 0.2~0.5 A | 미측정 | 미측정 | 미측정 | 혼 재질/온도 기재 |
| 1.5 A | 미측정 | 미측정 | 미측정 | 연속 작업 |
| 3 A | 미측정 | 미측정 | 미측정 | 연속 작업 |
| 최대 5.5 A | 미측정 | 미측정 | 미측정 | 정상 피크 지속시간 기재 |

브릿지 콘덴서와 T1의 손상은 잘못된 위상·공진 모드로 과도한 스트레스가 발생했을 가능성 외에도, 정격/리플 전류/과전압/발열/권선·코어 조건 등과 관련될 수 있다. 고장 원인을 펌웨어로 확정하지 않았다. DC 입력전류가 정상처럼 보여도 브릿지 내부의 무효전류나 특정 부품 전압까지 정상이라고 보장할 수 없다.

특히 CNT는 DRV에서 분주한 **발진기 출력**이다. 브릿지 피드백 트랜스가 끊어져도 LM565가 자유발진하면 CNT가 남을 수 있다. 현재 배선의 CNT만으로 ‘피드백 정상’이나 ‘PLL 잠금’을 판정하지 않는다.

다른 혼으로 교체되었는지 알아내는 식별 센서/명령도 현재 없다. EEPROM 설정이 유효하다는 사실은 **지금 장착한 혼에 적합하다**는 뜻이 아니다. 교체 후 무부하 확인 절차를 시스템에서 보장할 방법이 별도로 필요하다.

## 6. 검증 결과와 남은 실물 시험

호스트 C 테스트 9개가 통과했다.

IAR 기본 빌드는 ATmega8 오류 0/경고 0, ATmega16A 오류 0/기존 미사용 변수 경고 4개다. 운전 중 추적 분기의 별도 컴파일도 오류 0/경고 0으로 확인했다.

- 27개의 내부 최소점 × 29개의 시작 코드에 대한 탐색, 양쪽 경계, 평탄 응답, 측정 실패.
- 저장 실패, CRC 손상, 순번 순환, 불필요한 쓰기 생략, 기존 데이터 보존.
- 모든 저장 쓰기 위치에서 전원 중단 및 중단된 바이트의 256가지 값을 모의하여 이전/새 정상 레코드 중 하나로만 복원되는지 확인.
- 저장·최종 코드 적용이 확인된 다음에만 완료 통지가 나가는지 확인.
- 3초 유지, 놓으면 초기화, 누른 채 재시작 방지, 운전 중 시작 억제.
- PWM의 제한된 상승/하강, 고정 목표, 안정 후 탐색 시작.
- AD5280 쓰기/읽기 순서, 각 단계 NACK·무응답·STOP 정지·읽기 불일치.
- 튜닝 중 과전류 검사, 오류 유지, 출력 차단 요청.
- 기존 LCD 초기화와 시작/업로드 알림 회귀 테스트.

실행 명령:

```powershell
.\.vscode\test-firmware.ps1
.\.vscode\build-iar.ps1 -Target ATmega8
.\.vscode\build-iar.ps1 -Target ATmega16A
```

두 MCU는 함께 갱신하는 것을 전제로 한다. 새 `0x1C` 준비 명령, `0x1A` 제어 오류와 변경된 튜닝 절차 때문에 구형/신형을 섞은 운전은 검증하지 않았다. 기존 55/65/75/100 단계 출력 상승 경로는 새 초기 튜닝에서 사용하지 않는다.

실물 시험은 다음 순서로 진행한다.

1. 실장 회로와 SW3, 16 MHz 클록, 센서 방향·기준전압, 기존 플래시/EEPROM/퓨즈를 확인한다.
2. 실제 출력 차단 경로를 확인하고, 낮은 에너지의 시험 조건에서 오류 시 SD/HO/LO가 차단되는지 확인한다. 전원 인가 초기의 AD5280 중간값 상태도 확인한다.
3. EEPROM 코드와 RDAC 읽기값, TP6–TP7 및 실제 합성 저항을 확인한다. 전원을 껐다 켠 뒤도 비교한다.
4. 전류/ADC 보정, 무부하 초기 튜닝의 반복성, 출력 고정과 위상 조정 후 안정 시간을 측정한다.
5. 브릿지 피드백 유무와 파형, 주요 콘덴서 양단 전압·리플과 T1 발열을 확인한다. 손상 부품의 정격·고장 형태도 기록한다.
6. 혼 교체, 무부하 열상승, 압착 부하 변화별로 주파수·DC 전류·출력·AD5280 코드 기록을 비교한다.
7. 위 결과로 한계와 탐색 허가 조건을 확정한 뒤 운전 중 추적을 활성화한다.
