# 초기 자동 튜닝 동작과 검증 기록

> 2026-11-08: [최신 1분 제한·복귀 사양](./PLL_TUNE_TIMEOUT_2026-11-08.md)을 적용했다.

> 후속 수정으로 운전 중 보정이 추가되었다. 초기 자동 튜닝 절차는 유지한다.
> 아래 ‘다음 튜닝까지 고정’, ‘운전 중 추적 비활성’, ‘작업 분류 미구현’은 이전 상태다.
> 현재 운전 중 동작과 두 MCU 갱신 조건은 [운전 중 보정 사양](./PLL_RUNTIME_TUNING_SPEC.md)을 우선한다.

2026-11-07 사용자 설명을 반영한 현재 사양이다. **3초는 START 버튼을 누르는 시간**이며, 튜닝 완료 제한 시간이 아니다. 기존 코드에서 이 입력은 `A_TUNE/PB7`이다. 실제 패널의 START와 PB7 연결은 장비에서 확인해야 한다.

## 사용 순서

1. 혼을 장착하고 접촉·압력이 없는 상태에서 초기 수동 PHASE2 조정을 한다. PHASE2와 AD5280은 함께 연결된 상태를 전제로 한다.
2. 정지 상태에서 기존 튜닝 버튼을 약 3초 누르면 자동 튜닝을 시작한다. 버튼을 계속 누르고 있어도 중복 시작하지 않는다.
3. 노브 위치와 관계없이 PWM을 `OCR2=128`로 서서히 맞춘다. 현재 Phase Correct PWM에서 듀티는 128/255, 약 50.2%다. **전력 정격의 50%라는 의미는 아니다.** 목표에 도달한 후 두 틱 동안 유지하고 탐색을 시작한다.
4. AD5280의 현재 코드와 좌우 한 칸의 전류를 측정하며 낮은 쪽으로 이동한다. 각 설정에서 약 819 ms 안정 후 약 164 ms 동안 32개 ADC 값을 모은다.
5. 같은 코드에서 양쪽보다 전류가 확실히 낮은 결과가 **3회 연속** 확인될 때까지 반복한다. 매 회 중심점을 앞뒤로 다시 측정하고, 좌우 방문 순서도 교대한다. 잡음·시간 변화·평탄한 응답으로 판단이 모호하면 확인 횟수를 초기화하고 계속 측정한다.
6. 확인된 최소점이 코드 `D`이면 **`D+1`을 최종 운전값**으로 적용한다. 마지막 측정값이 직전 같은 위치의 전류와 일치하는지도 확인한다. 불일치하면 다시 최소점을 확인한다.
7. 최종 코드와 그 위치의 주파수 계수를 EEPROM에 쓰고 읽어 검증한 뒤에만 완료를 알린다. 정상 대기 출력으로 복귀한다.
8. 전원을 다시 켜면 최신 정상 저장값을 읽어 AD5280에 적용하고 RDAC 읽기로 확인한다. **다음 수동 자동 튜닝 전까지 이 코드를 유지한다.** LM565 자체의 주파수 추종은 계속 동작한다.

현재 회로의 A-W 저항은 코드 증가 시 감소한다. 사용자가 확인한 ‘최저점에서 저항이 낮고 주파수가 높은 쪽 한 칸’을 `D+1`로 반영했다. 저항 방향은 [AD5280 데이터시트](https://www.analog.com/media/en/technical-documentation/data-sheets/AD5280_5282.pdf)의 A-W 특성에 근거한다. 실제 주파수 변화 방향은 장비에서 확인해야 한다. 다음 튜닝에서도 최소점을 새로 찾으므로 매번 저장 코드에 단순히 1을 누적하지 않는다.

## 완료 조건과 중단 조건

2026-11-08 수정본은 출력 준비부터 전체 튜닝을 약 60초로 제한한다. 전류 곡선이 평탄하거나 계속 흔들려 시간 안에 최소점을 찾지 못하면 저장하지 않고 직전 AD5280 값으로 복귀한 뒤 오류 차단한다. ‘정확한 최저점’은 무한 정밀도의 수학적 최소가 아니라 **현재 ADC 분해능과 비교 문턱으로 반복 확인한 이산적인 국소 최소점**이다. 서로 다른 공진 모드 중 올바른 모드를 판별하는 기능은 아니다.

기존 코드 범위 221~249는 유지한다. 경계에서 양쪽 최소점 검증이 불가능하면 실패 처리하며, 범위를 임의로 넓히지 않는다. 전류 비교 문턱은 32개 합계 기준 16, 평균 ADC 약 0.5단계다. 이 차이를 실물에서 구별하지 못하면 튜닝이 끝나지 않을 수 있으므로 센서 분해능과 문턱을 측정해 조정해야 한다.

ATmega8은 약 512 ms마다 진행 메시지 `0x1D`를 보낸다. ATmega16A는 탐색 시작 요청 후 약 2초간 응답/진행 통지가 없으면 오류 처리한다. 이는 총 튜닝 시간 제한과 다르다. 과전류, I2C 쓰기/읽기 실패, 측정 실패, 중단 명령, 탐색 경계 오류에서도 성공으로 저장하지 않는다. 실패 시 기존 저장 코드를 복원하고 오류를 유지한다. 현재 일반 키/REMOTE 운전은 튜닝 중 억제되며, 별도의 사용자 취소 버튼 동작은 추가하지 않았다.

정상 정지 중 미세 출력은 기존대로 유지한다. 오류 때는 `SONIC_OUTPUT=0`, `OCR2=0`을 요청한다. 실제 게이트 출력 차단은 실물에서 확인해야 한다.

## 저장 방식

ATmega8 EEPROM의 `0x100~0x107`, `0x108~0x10F` 두 슬롯을 번갈아 사용한다. 코드·16비트 주파수·순번·반전값·CRC를 검사하고, 유효 표시는 마지막에 기록한다. 이전 정상 슬롯을 남겨 두어 쓰기 중 전원 중단을 대비한다. 같은 코드와 주파수 계수이면 재기록을 생략한다.

새 슬롯이 없으면 유효한 구형 저장 코드를 사용한다. 새/구형 모두 유효하지 않으면 233으로 대기와 초기 튜닝을 허용하지만 정상 운전은 막는다. 전원 강하로 CPU 자체가 오동작하는 모든 상황까지 보장하는 것은 아니므로 실물 전원 차단·재기동 시험이 필요하다.

운전 중 추적은 `PLL_RUNTIME_TRACKING_ENABLED=0`으로 유지했다. 작업 중 코드 변경이나 EEPROM 갱신은 하지 않는다.

## 작업 종류 판정에 대한 답변

사용자가 설명한 간격은 **전류 상승 시작과 다음 상승 시작 사이의 시간**이다. MCU가 이 간격을 측정해 반복 패턴을 추정할 수 있다. 아래는 후속 설계안이며 이번 펌웨어에 작업 분류 기능을 추가한 것은 아니다.

| 여러 번 관측한 상승 시작 간격 | 임시 판정 |
|---|---|
| 1초 이내가 3~5회 연속 | 빠른 반복 작업 후보 |
| 2초 이상이 3~5회 연속 | 느린 반복/프레스 작업 후보 |
| 1~2초, 불규칙, 관측 부족 | 미확정 |

전류 필터와 상승/복귀 문턱을 따로 두는 히스테리시스를 사용하고, 한 번 올라간 전류가 충분히 내려오기 전에는 새 상승으로 세지 않아야 한다. PWM 변경·기동·튜닝 중의 변화는 제외한다. 일정한 고전류가 유지되는 연속 작업에는 상승 사건이 반복되지 않을 수 있으므로 이 기준만으로 모든 작업을 구별하지는 못한다. 초기 판정까지는 관측 시간이 필요하고 작업 중 패턴 변경도 재판정해야 한다.

분류가 가능하더라도 같은 전류 상승이 온도, 압력, 출력 변화 중 어느 원인인지는 별도 문제다. 따라서 ‘연속 작업이면 무조건 낮은 주파수 쪽으로 계속 이동’하는 방식은 적용하지 않았다. 열상승이 확인된 조건에서 낮은 주파수 방향을 우선 시험하더라도, 이동 한계·전류 개선 확인·악화 시 복귀·냉각 또는 작업 변화 시 중단이 필요하다. 특히 현재 한 위치 측정에 약 1초가 걸리므로 1초 이내 반복 작업 중 인접 위치를 단순 순차 비교하면 서로 다른 압력을 비교할 수 있다. 후속 운전 중 튜닝은 작업 주기와 비교 구간을 맞추거나 별도 부하/위상 정보를 확보해야 한다.

## 검증 결과와 실물 확인 항목

- 호스트 C 테스트 **10개 통과**: 783개 시작/최소점 조합, 최소점+1 적용, 반복 튜닝 시 오프셋 누적 방지, 평탄 응답의 반복 측정, 불안정 후 수렴, 확인 도중 최소점 이동, 측정 실패, 저장 실패와 전원 중단 모의, 부팅 설정 복원, PWM 고정, 장시간 진행 메시지와 통신 시간 초과, 기존 보호/LCD/알림.
- IAR 빌드: ATmega8 오류 0/경고 0, ATmega16A 오류 0/기존 미사용 변수 경고 4개.
- 실제 MCU에 기록하지 않았다. 실제 전류 최소점, 50% PWM 파형, 재기동 후 RDAC, 차단 경로와 부품 발열은 아직 검증하지 않았다.

ADC 차단값 450/500은 기존 값이며 **5.5 A로 보정된 값이 아니다.** 사용자 작업 상한 5.5 A에 맞춘 센서 보정과 피크 지속시간 측정은 남아 있다. DC 입력전류가 작아도 브릿지 내부 전압·무효전류까지 정상이라고 보장하지 않으므로 피드백 트랜스/콘덴서 고장 방지는 별도 실측이 필요하다.

두 MCU를 함께 갱신하는 후보이며 구형/신형 혼용은 검증하지 않았다. 빌드 결과는 `.build/Atmega8_LM565_BD/Release/Exe/`, `.build/Atmega16A_LM565_BD/Release/Exe/`에 생성된다. 기존 보드 폴더의 `Release` 파일은 이번 빌드 결과가 아니다.

이번 수정 직전 백업은 `.build/before_fixed50_tuning_20261107_223606/`이다. 최초 코드 분석과 회로·보호 관련 상세 내용은 [1차 검토 기록](./PLL_TUNING_REVIEW_2026-11-07.md)에 있다.
