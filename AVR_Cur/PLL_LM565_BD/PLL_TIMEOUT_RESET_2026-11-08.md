# START 3초로 튜닝 시간 초과 해제

2026-11-08 사용자 요청: 튜닝 시간 초과는 전원 차단 없이 START 3초로 해제하고, 과전류·통신 이상은 전원 재시작까지 오류를 유지한다.

## 사용 방법

1. 1분 내 튜닝하지 못하면 기존처럼 출력 차단, `Tuning ERROR`, 지속 부저가 발생한다.
2. REMOTE를 정지로 놓고 START를 한 번 놓은 뒤 약 3초 누른다.
3. ATmega8의 복구 확인 응답을 받으면 부저와 오류를 해제하고 STOP으로 돌아온다. STOP의 기존 미세 출력은 복원한다. RUN은 자동으로 시작하지 않는다.
4. START를 계속 누르고 있어도 자동 튜닝으로 이어지지 않는다. 다시 튜닝하려면 버튼을 놓고 새로 3초 눌러야 한다.

ATmega16A와 ATmega8 모두 갱신해야 한다. 기존의 저장된 튜닝값은 보존하며, 복구 과정에서 EEPROM에 새 튜닝값을 쓰지 않는다. AD5280은 시간 초과 시 복귀했던 튜닝 직전 코드로 유지한다.

## 해제 가능한 오류와 불가능한 오류

- 1분 제한 도달 및 EEPROM 저장 완료 여유 시간 부족에 따른 중단만 버튼으로 해제할 수 있다.
- 과전류, ADC 이상, AD5280 통신·설정 확인 실패, 튜닝 진행 통지 중단, 복구 확인 응답 시간 초과 등은 버튼으로 해제하지 않는다.
- 시간 초과 이후 다른 오류가 발생하면 해제 가능한 상태를 취소한다. 이후 시간 초과 통지가 다시 와도 심각한 오류를 덮어쓰지 않는다.
- ATmega16A는 차단 상태에서도 자기 전류 ADC를 확인하고, ATmega8은 복구 요청 때 ADC 범위·갱신 여부와 AD5280 재설정·읽기 검증을 확인한다.
- 과전류의 실제 암페어 환산은 이번 변경 범위가 아니다. 기존 ADC 기준을 유지했다.

## 통신과 상태 처리

- `0x1E`: 시간 초과 통지. 기존 `0x12`, `0x1A`는 버튼 해제 불가 오류로 유지한다.
- `0xB2`: 시간 초과 복구 요청, `0xB3`: 확인 응답.
- `0xB4`: 새 ATmega16A의 복구 기능 지원 통지. ATmega8은 이를 받기 전에는 구형 패널도 출력을 차단하도록 기존 오류 코드를 보낸다.
- 복구 요청은 약 100.8ms마다 재전송한다. 약 2초 내 응답이 없으면 해제 불가 오류로 전환한다. ACK가 유실되면 ATmega8은 재요청에 다시 응답한다.
- ATmega8은 복구 시 남은 RUN/튜닝 명령과 출력 안정 허가를 비우고 정지 상태를 유지한다.
- ATmega16A의 UART 수신에서는 해제 불가 오류가 시간 초과·확인 응답보다 우선한다.

## 검증

- 호스트 C 시험 14개 통과. 시간 초과 복구, 다른 오류 거부, ADC 갱신 중단, AD5280 실패, ACK 유실·재요청, 응답 시간 초과, 오류 우선순위, 3초 미만 입력·버튼 놓기·계속 누름, STOP 복귀를 포함한다.
- ATmega8 IAR 빌드 오류 0/경고 0. Flash 6,443바이트, DATA 448바이트(스택 예약 포함, 별도 absolute 영역은 MCU 레지스터).
- ATmega16A IAR 빌드 오류 0/기존 미사용 변수 경고 4개. Flash 5,486바이트, DATA 693바이트(스택 예약 포함).
- 스택 계산: ATmega8 CSTACK 64/192, RSTACK 22/128바이트. ATmega16A CSTACK 39/128, RSTACK 28/128바이트. 추가 16바이트 여유 검사까지 통과했다.
- 변경 전 백업: `.build/before_timeout_reset_20261108_005431/`.
