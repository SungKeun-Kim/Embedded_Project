# ATmega8 초기값 220 / 범위 185~255

2026-11-08 사용자 지정: AD5280 초기값 220, 위아래 35코드의 조정 여유.

## GANG에 등록할 파일

| PRO ISP IV 항목 | 파일 | 용도 |
| --- | --- | --- |
| Flash Data | `ATmega8_FLASH_CENTER220_RANGE185_255.hex` | 초기값 220, 허용 범위 185~255인 새 펌웨어 |
| EEPROM Data | `ATmega8_EEPROM_INITIAL220.hex` | 저장 설정을 코드 220으로 초기화 |

**이번 요청대로 220에서 새로 시작하려면 두 파일을 함께 등록한다.** Flash만 바꾸고 EEPROM을 보존하면 기존에 저장된 코드가 우선한다. EEPROM 초기화 파일은 각 장비의 이전 튜닝값을 지우므로, 개별 튜닝값을 유지하는 업데이트에는 사용하지 않는다.

파일은 표준 Intel HEX이고 시작 주소는 각 메모리의 0이다. Flash 데이터는 6,439바이트, EEPROM 데이터는 512바이트다. Flash와 EEPROM 메모리 영역을 구분해서 불러온다. MCU는 ATmega8을 선택하며 퓨즈·잠금 설정은 별도로 확인한다. 파일에 퓨즈값은 포함하지 않았다.

매뉴얼 기준 사용 순서: U 모드 → PC에서 MCU/퓨즈/잠금/두 파일 설정 → Transfer로 프로그래머에 저장 → T 모드 → 전원이 공급된 대상 보드 연결 → Programming 버튼. Memory LED 초록색은 프로그래머에 데이터가 저장됐다는 뜻이고, Target LED 초록색은 보드 기록 성공 표시다. 실제 장비의 EEPROM을 읽어 검증할 수 있다면 초기값과 아래 초기화 영역도 확인한다.

ATmega16A는 기존 START 3초 시간 초과 복구 버전과 바이트 단위로 같으므로, 해당 버전이 설치되어 있다면 다시 기록하지 않는다.

## 초기 EEPROM의 내용

| EEPROM 주소 | 데이터 | 의미 |
| --- | --- | --- |
| `0x0002` | `0xDC` = 220 | 최초 적용할 AD5280 코드 |
| `0x0003` | `0x7D` = 125 | 구형 펌웨어 호환용 주파수 참고값 |
| `0x00FF` | `0x55` | 구형 설정 형식의 유효 표시 |
| 나머지 전체 | `0xFF` | 비어 있는 상태 |

원래 `Atmega8_LM565_BD/eep.hex`와 비교하면 주소 `0x0002`만 233에서 220으로 바뀐다. 원래 파일은 보존했으므로 이번 초기화에는 이 패키지의 `ATmega8_EEPROM_INITIAL220.hex`를 사용한다.

### 구형 주파수 참고값 125

예전 펌웨어가 EEPROM 주소 `0x0003`에 저장하고 읽던 1바이트 참고값이다. **125Hz 또는 125kHz를 뜻하지 않으며 발진 주파수를 그 값으로 설정하는 항목도 아니다.** 옛 측정·변수 형식에 종속된 값이다.

현재 펌웨어는 구형 설정을 읽을 때 주소 `0x0002`의 AD5280 코드와 `0x00FF`의 유효 표시만 사용하고, `0x0003`은 주파수로 읽지 않는다. 구형 1바이트 값에서 실제 16비트 주파수 계수를 복원할 수 없기 때문이다. 이번 초기 파일에는 구형 호환을 위해 원래 값 125를 그대로 둔다.

자동 튜닝에 성공하면 현재 측정한 주파수 계수(16비트)와 AD5280 코드 등을 새 기록 형식에 저장한다. 이때 주소 `0x0003`에도 호환용 하위 1바이트가 복사된다. 따라서 이 값이 125와 달라져도 그 자체로 오류는 아니다.

### 유효 표시 0x55

펌웨어가 “구형 형식의 설정이 들어 있다”고 판단하는 식별값이다. 코드가 허용 범위인지도 함께 검사한다. **공구혼이 실제로 최적 튜닝됐다는 증명, 전체 EEPROM 체크섬, MCU 퓨즈값은 아니다.**

이번 파일에는 코드 220과 유효 표시를 함께 넣으므로 구형 호환 설정으로 인식하고 일반 RUN을 허용한다. 실제 최적 공진 여부는 공구혼을 장착한 뒤 별도로 튜닝해 확인해야 한다. EEPROM이 완전히 비어 있으면 기본 코드 220을 적용하지만, 유효한 저장 설정이 없으므로 일반 RUN은 허용하지 않고 자동 튜닝 성공이 필요하다.

새 튜닝 기록은 `0x0100~0x010F`의 두 슬롯에 보관하며, `0xA5` 표식·버전·순번·코드·16비트 주파수 계수·반전값·CRC로 검사한다. 새 기록이 유효하면 구형 주소 `0x0002`보다 우선한다. **220으로 초기화하려면 기존 새 기록도 없어져야 하므로, 이번 파일은 이 영역을 모두 0xFF로 지정한다.** 프로그래머가 0xFF 쓰기를 생략하면서 EEPROM을 보존한다면 기존 기록이 남을 수 있으므로, 초기화 시 이 영역까지 지워졌는지 확인한다.

## 조정 범위와 유지되는 동작

- 허용 범위: **185~255**, 71개 코드, 초기값 220.
- 초기 자동 튜닝은 기존처럼 국소 최소점을 반복 확인하고 높은 주파수 쪽 한 칸(+1)을 최종값으로 저장한다. 최소점이 254이면 최종값 255까지 저장할 수 있다.
- 범위의 끝 185 또는 255에서 전류가 최소라면 양쪽 비교가 불가능하므로 튜닝 성공으로 저장하지 않는다. 255를 넘겨 0으로 돌아가는 동작은 금지된다.
- **1분 제한은 유지한다.** 한 칸씩 안정화·측정하는 기존 방식이므로 71개 코드를 1분 안에 모두 조사하는 전 범위 스캔을 의미하지 않는다. 최저점이 멀면 탐색 도중 시간 초과로 중단할 수 있다.
- 초기값이나 허용 범위를 바꾸어도 실제 발진 주파수가 자동으로 보장되지는 않는다. 기존 주파수 검사 범위 약 19.2~20.6kHz와 과전류 검사는 유지한다.
- 운전 중 보정은 기존처럼 저장 기준에서 낮은 주파수 방향으로 최대 3칸이다. 이번 ±35는 초기 튜닝 허용 범위이며 운전 중 35칸 이동을 허용한 변경은 아니다.
- START 3초로 튜닝 시작, 시간 초과 후 START 3초 복구, 과전류·통신 오류의 전원 재시작 정책은 유지한다.

## 검증과 기록 상태

- IAR 빌드 오류 0/경고 0.
- 모의 시험 14개 통과. 71개 코드 전송, 초기 코드/유효 표시 해석, 양 끝 코드 저장, 254 최소점에서 최종 255 저장, 오버플로 방지, 넓어진 범위에서도 1분 제한 및 저장 금지 등을 확인했다.
- CSTACK 계산 사용량 64/192바이트, RSTACK 22/128바이트. 각각 추가 16바이트 여유 검사까지 통과했다. DATA 사용량은 스택 예약 포함 448/1,024바이트다.
- Flash HEX는 새 IAR 빌드와 주소별 데이터가 동일하고, EEPROM HEX는 512바이트 재해석·체크섬 검증을 통과했다.
- **이번 수정본은 파일로만 만들었으며 장비에 업로드하거나 확대 범위의 실기 시험을 하지 않았다.**
- 패키지는 `UPLOAD COMPLETE` 표시용 EEPROM 표식을 넣지 않는다. PRO ISP의 기록 결과로 성공 여부를 확인한다.

`manifest.json`에는 설정값과 파일 SHA-256을 기록했다.
