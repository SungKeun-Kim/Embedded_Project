# LM565 PLL 펌웨어 기능 및 개선 검토

> 이 문서는 2026-11-06 소스의 **수정 전 동작 기록**이다.
> 2026-11-07 변경된 코드와 현재 검증 상태는
> [PLL 자동 튜닝·저장·보호 검토](./PLL_TUNING_REVIEW_2026-11-07.md)를 우선 참조한다.

## 1. 문서의 목적과 범위

이 문서는 2026-11-06 현재 작업 폴더의 **소스 코드 정적 분석**과
[PLL_LM565_BD_Schematic.pdf](./PLL_LM565_BD_Schematic.pdf)를 바탕으로,
ATmega16A와 ATmega8의 현재 동작을 정리한 기준 문서다. 향후 PLL 동작을
개선할 때 현재 기능을 보존하고, 의도와 다른 동작을 재현·수정하는 데
사용한다.

- 코드에 실제로 실행되는 경로와, 주석 처리되었거나 프로젝트에 포함되지
  않은 기능을 구분했다. 파일이나 변수 이름만으로 기능을 판단하지 않았다.
- 아래의 시간과 주파수 환산은 제공된 회로도의 **두 MCU 16 MHz**를
  전제로 한 명목값이다. 인터럽트 지연, 외부 신호, 실제 보드 부품에 따라
  달라진다.
- 이 분석 과정에서는 MCU를 다시 읽거나 동작 파형을 측정하지 않았다.
  실행 중 동작, PLL 잠금, 출력 안전성은 별도 실물 검증이 필요하다.
  이전 업로드 작업에서는 두 보드의 플래시·EEPROM 검증과 `UPLOAD COMPLETE`
  표시가 확인되었지만, 그것이 전체 PLL 기능 검증을 뜻하지는 않는다.
- 이 문서는 문제를 식별하고 검증 계획을 제시하며, 펌웨어 동작은 수정하지
  않는다. 증상이나 회로 영향이 확정되지 않은 항목은 **확인 필요**로 둔다.

## 2. 회로와 역할 분담

제공 회로도에는 ATmega16A(U1), ATmega8(IC2), LM565C(U4),
AD5280BRUZ20 디지털 가변저항(IC3), ACS712 전류 센서(IC1),
HEF4520 카운터(U2), IR2104 게이트 드라이버(U6)가 표시되어 있다.
실제 보드가 이 회로도와 같은 개정판인지, SW3의 설정과 부품값이
일치하는지는 별도 확인이 필요하다.

```text
조작 입력 / LCD / PWM / 오류 출력  <->  ATmega16A
                                          |
                                     UART 8N1
                                          |
전류 센서 CURRENT -> ATmega8 ADC    ATmega8 -> I2C -> AD5280
         |                     CNT -> 양 MCU        |
         +-> ATmega16A ADC          HEF4520 <- DRV <- LM565 주변 회로
                                      LM565 / 드라이버 / 출력 회로
```

| 회로 연결 | 현재 코드와의 관계 |
|---|---|
| `CURRENT` | ACS712와 후단 회로의 신호가 ATmega16A PA2/ADC2와 ATmega8 PC0/ADC0에 연결된다. 두 MCU가 서로 다른 조건으로 읽는다. |
| `CNT` | HEF4520의 `2Q2` 측 신호가 ATmega16A PD2/INT0와 ATmega8 PD3/INT1에 연결된다. ATmega16A는 하강 에지, ATmega8은 상승 에지를 센다. |
| `SCL`, `SDA` | ATmega8 PC5/PC4와 AD5280의 I2C 연결이다. 코드의 전송 주소 바이트는 `0x58`이며 7비트 주소로는 `0x2C`다. |
| `DIGIPOT_A`, `DIGIPOT_WB`, `PHASE1_WB` | AD5280 및 SW3를 통해 LM565 주변 아날로그 경로와 연결된다. 스위치 상태를 포함한 실제 연결을 확인해야 한다. |
| `SONIC_ON`, `PWM_SIG` | ATmega16A PD6과 PD7/OC2에서 나와 드라이버 주변 회로에 연결된다. 소프트웨어 변수 이름만으로 최종 출력의 안전한 켜짐/꺼짐 극성을 단정하지 않는다. |
| `RXD`, `TXD` | ATmega16A PD0/PD1과 ATmega8 PD1/PD0가 교차 연결된다. |
| LCD | ATmega16A PC0/PC1/PC2가 RS/RW/E, PC4~PC7이 DB4~DB7이다. |
| 조작 입력 | ATmega16A PB0 `SEL`, PB1 `REMOTE`, PB7 `A_TUNE`, PB4~PB6 `MODE/DOWN/UP`이 회로도에 표시된다. 현재 실행 코드의 주요 입력은 PB0, PB1, PB7이다. |

회로도는 U2의 두 번째 카운터 출력 `2Q2`를 `CNT`에 연결한다. 일반적인
바이너리 카운터 해석에서는 구동 입력의 **1/8**이지만, 신호 극성·실제
분주 및 파형은 측정으로 확인해야 한다. 별도의
[Welder_Disp_V1.pdf](./Atmega16A_LM565_BD/Welder_Disp_V1.pdf)에는 11.0592 MHz
표기가 있어 제공된 최신 PLL 회로도와 다르다. 이 문서는 요청받은 PLL
회로도의 16 MHz를 기준으로 하며, 실제 장착된 크리스털 확인 전에는 어느
문서가 실물과 일치하는지 확정하지 않는다.

## 3. ATmega16A: 표시·운전·출력 제어

### 3.1 기동과 기본 설정

1. 포트, Timer0, ADC, Timer1/Timer2, LCD, INT0, UART를 초기화한다.
2. EEPROM 식별값 `0xAA55`를 최대 20회 읽고, 없으면 현재 기본값을
   EEPROM에 기록한다. 유효한 식별값이 있으면 설정값을 불러온다.
3. `ResetInit()`에서 운전 상태를 정지 상태로 만들고, 오류 플래그를
   지우며, PWM 기준값 `ucPwmmin`과 `OCR2`를 77로 설정한다.
4. 시작 화면 `ULTRA SONIC / WELDER` 뒤에 기본 `P/L: ... 00.0kHz` 화면을
   표시하고 메인 루프에 진입한다.

LCD는 4비트, 2줄 모드로 재동기화하여 초기화한다. 코드에는 Timer1
초기화도 있으나 현재 실행 경로에서 스위프를 시작하는 호출은 확인되지
않는다.

### 3.2 운전 입력과 상태

| 조건 | 현재 코드 동작 |
|---|---|
| PB1 `REMOTE`가 Low | `sonic_on()`, `funRemote_on()`을 실행한다. `ucPortdFlag=0x10`, 운전 화면을 표시하고 상태 전환 시 ATmega8에 `0x21`을 한 번 보낸다. |
| PB1 `REMOTE`가 High | `sonic_off()`, `funRemote_off()`을 실행한다. `ucPortdFlag=0`, 정지 화면, `OCR2=77` 및 출력 계산 기준값 77을 설정하고 상태 전환 시 `0x29`를 보낸다. |
| PB0 `SEL` High | 화면에 `PULSE`, PWM 변화량 `PWM_STEP=3`을 설정한다. |
| PB0 `SEL` Low | 화면에 `CONT.`, PWM 변화량 `PWM_STEP=1`을 설정한다. |
| PB7 `A_TUNE` Low를 정지 중 유지 | 약 10회의 100.8 ms 기준 틱 후 ATmega8에 `0x17`을 보내고 튜닝 모드로 들어간다. 두 `SEL` 분기는 현재 모두 `0x17`이다. |

`PULSE`와 `CONT.`라는 표시만으로 정해진 주기의 초음파 펄스가 구현되었다고
판단할 수 없다. 현재 확인되는 차이는 화면과 PWM 목표값 접근 단계다.
또한 `sonic_off()`의 `SONIC_OUTPUT = 0`은 주석 처리되어 있다.
`SONIC_OUTPUT`/실제 드라이버의 극성 및 정지 시 안전 상태는 8절에서 별도
검증해야 한다.

### 3.3 PWM 및 설정 표시

- Timer2는 위상 보정 PWM, 분주 8로 설정된다. 16 MHz 및 8비트 위상 보정
  기준 명목 PWM 주파수는 `16 MHz / (8 × 510) ≈ 3.92 kHz`다.
- 정상 운전 중 ADC0 값을 10으로 나누고 90으로 제한한 뒤,
  목표 비교값을 `입력 × (253 - 80) / 90 + 77`로 계산한다. 코드상
  목표 범위는 **77~250**이다. 정지 중에는 `OCR2=77`로 돌아간다.
- `ocrdata_cnt`를 목표값 방향으로 `PWM_STEP`만큼 변화시켜 `OCR2`에
  기록한다. 두 비교가 독립된 `if`이므로 목표값을 건너뛰는 경우의
  실제 수렴은 8절의 확인 항목이다.
- 운전 화면의 `P/L` 숫자는 제한된 입력에 10을 더한 값으로 표시한다.
  ADC0 입력은 제공 회로도의 `PWM_VR` 경로다.
- 튜닝 진행 메시지 `0x13`~`0x16` 수신 시 각각 OCR2에 `0x8C`, `0xA6`,
  `0xC0`, `0xFD`를 직접 쓴다. 표시 문자열의 55/65/75/100은 코드의
  단계명이며, 실제 출력 전력의 비율을 보증하지 않는다.

[init_time.c:79](./Atmega16A_LM565_BD/init_time.c#L79),
[main.c:172](./Atmega16A_LM565_BD/main.c#L172).

### 3.4 주파수 표시

- `CNT` 하강 에지를 INT0에서 센다. Timer0 비교 인터럽트 100회마다
  누적값을 `f_data2`에 복사하고 카운터를 0으로 만든다.
- 16 MHz, `OCR0=62`, 분주 256 기준 비교 주기는 약 1.008 ms, 100회는
  약 100.8 ms다. `frequency()`는 호출 시점에 읽은 최근 값 8개의
  이동 합에서 12를 뺀 다음 10으로 나누고, 두 번째 줄에 소수점 한 자리의
  `kHz` 숫자를 출력한다.
- 8개는 **함수 호출 시 읽은 값**이므로 반드시 서로 다른 100.8 ms 샘플
  8개라고 보장할 수 없다. 정지 시 표시값은 `00.0`이다.
- HEF4520 분주비를 포함해 실제 주파수와 표시값을 교정해야 한다.

### 3.5 과부하 처리

정상 운전 모드에서 약 100.8 ms 틱마다 ADC0과 ADC2를 읽고 `error_chk()`를
호출한다. ADC2가 `500` 이상인 판정이 연속 5회 발생하면
`OVER LOAD / ERROR !!!`을 표시하고, `ErrorFlag=1`, 비퍼 및 오류 출력
상태를 설정하며 `sonic_off()`와 `OCR2=0`을 실행한다. 이후 메인 루프의
`if(ErrorFlag) while(1);`에 들어간다. 이 코드는 자동 복구나 오류
해제 절차를 제공하지 않는다.

ADC2 신호는 회로도의 `CURRENT`이지만, 센서와 아날로그 후단의 기준점·이득을
실측하지 않고 ADC 코드 500을 특정 전류값으로 환산할 수 없다.
특히 튜닝 모드에서는 정상 운전의 ADC 갱신과 `error_chk()`가 호출되지
않는 점을 반드시 검토해야 한다.

## 4. ATmega8: 전류 탐색·디지털 저항·주파수 보정

### 4.1 기동과 하드웨어 접근

ATmega8은 포트, ADC, Timer0, I2C, INT1, UART를 초기화하고 EEPROM에서
기준 저항 코드와 기준 주파수 코드를 읽는다. 기준 저항 코드가 221~249
범위 밖이면 233으로 대체한다. EEPROM 식별 바이트가 없으면 저항 코드
233, 주파수 코드 `0x7D`를 기록한다. 이후 시작 알림을 보내고
`TWI_data(ucOrgpt)`로 AD5280에 기준 코드를 보낸다.

`TWI_data()`는 시작 조건, 주소 바이트 `0x58`, 제어 바이트 `0x00`,
데이터 바이트를 차례로 보내며 각 단계의 상태를 기다린다. `TWBR=0x72`,
분주 1, 16 MHz 기준 명목 SCL은 약 65 kHz다. 한 번의 함수 호출 마지막에
100 ms 지연을 두 번 수행한다. 상태가 기대값이 아닐 때 빠져나오는
타임아웃은 없다.

### 4.2 전류 샘플과 카운터

- `CNT` 상승 에지의 INT1에서 `f_data`를 증가시키고, PD5를 짧게 토글한
  뒤 ADC0을 읽어 `ADC_DATA`에 저장한다.
- ADC0 값이 `450`보다 크면 `ucError_flag=1`을 설정한다. 다만 이 플래그로
  튜닝을 중단하는 세 곳은 현재 모두 주석 처리되어 있다.
- INT1 에지 151회마다 `t2_cnt`를 증가시킨다. 메인 루프의 IDLE 상태에서
  `t2_cnt`를 확인해 주파수 보정 함수를 호출한다.
- Timer0 오버플로 때 카운터를 `0xB0`으로 다시 설정하고, 오버플로
  50회마다 8비트 `f_data`를 `f_data2`에 옮긴다. 16 MHz, 분주 1024,
  80카운트 기준 명목 오버플로는 약 5.12 ms이고 50회는 약 256 ms다.
  인터럽트 지연과 재장전 오차는 포함하지 않은 값이다.

### 4.3 튜닝 상태기계

| 수신 명령 | 현재 실행 경로 |
|---|---|
| `0x17` 직접 튜닝 | `ucOnschk=7`, `STOP`으로 설정한다. 다음 단계에서 `0x17`을 다시 보내고 탐색을 수행한 뒤, 단계 9에서 `0x19`를 보내 종료·저장한다. 현재 ATmega16A의 튜닝 키가 보내는 명령이다. |
| `0x11` 단계 튜닝 | `ucOnschk=2`, `STOP`으로 설정한다. 탐색 전 진행 단계 `0x13`, `0x14`, `0x15`, `0x16`을 순서대로 보내고, 단계 7에서 `0x19`를 보내 종료·저장한다. 현재 ATmega16A의 키 경로에서는 `0x11`이 아니라 `0x17`을 보낸다. |
| `0x21` 운전 | `ucRUNFlag=1`, 상태를 IDLE로 바꾸고 에지 카운터 일부를 초기화한다. |
| `0x29` 정지 | `ucRUNFlag=0`, 상태를 IDLE로 바꾼다. |

탐색에서는 기준 코드와 기준+1의 전류 샘플을 비교해 증가 또는 감소
방향을 정한다. 이후 한 단계씩 값을 변경하고 `ADC_DATA`가 더 작아지는지
비교한다. 값이 더 이상 작아지지 않으면 한 단계 되돌려 정지하며,
반복 횟수가 20에 이르면 정지한다. 코드에는 최초 비교와 각 단계에
여러 지연이 있으므로 순간적으로 끝나는 작업이 아니다.

튜닝 종료 시 현재 `ucOrgpt`와 `frequency()`가 얻은 `ucFreqNew`를
EEPROM에 저장한다. 이 절차가 실제 공진점·최대 출력·최소 발열 중 어느
물리량에 최적화되어야 하는지는 회로와 장비 요구사항으로 확인해야 한다.

### 4.4 운전 중 주파수 기반 저항 보정

IDLE에서 에지 이벤트가 누적되고 `ucRUNFlag=1`이면, 보정 함수의 호출
10회마다 `frequency()`로 `f_data2`를 `ucFreqNew`에 복사한다. 필터 관련
코드는 주석 처리되어 있어 이 경로에서 이동평균은 적용되지 않는다.

`ucFreqNew`가 `0x60`~`0x84` 범위일 때:

1. 새 코드가 저장 기준값보다 낮으면 `((기준 - 현재) / 2) + 1`을
   계산한다. 같거나 높으면 단계 1이다.
2. 단계 1은 기준 저항 코드를 쓰고, 단계 2~10은 기준 코드에서 각각
   1~9를 뺀 값을 쓴다. 그 외 단계나 허용 범위 밖의 주파수 코드에서는
   이 함수가 새로운 저항 코드를 쓰지 않는다.
3. 기준 코드는 이 보정에서 바뀌지 않고, EEPROM의 기준 주파수도
   튜닝 완료 시 갱신된다.

이는 아날로그 LM565 회로를 디지털 저항으로 보조 조정하는 코드 경로다.
이 코드만으로 PLL 잠금 여부를 직접 확인하거나 목표 주파수 추종 성능을
보장하지는 않는다.

## 5. MCU 간 UART

양쪽 모두 UART 분주값 25와 8비트 데이터 형식으로 설정한다. 16 MHz와
일반 속도 기준 명목 전송속도는 약 38,462 bit/s이며 코드의 이름은
38,400 baud다. 기존 제어 메시지는 단일 바이트이고 별도의 프레임,
체크섬, 명령 큐가 없다.

| 값 | 방향 | 현재 의미 |
|---|---|---|
| `0x11` | 16A → 8 | 단계 튜닝 명령. 현재 16A 키 경로에서는 전송하지 않음 |
| `0x17` | 16A → 8 | 직접 튜닝 명령 |
| `0x21` / `0x29` | 16A → 8 | 운전 시작 / 정지 |
| `0x12` | 8 → 16A | 튜닝 오류 표시 요청. 관련 오류 중단 경로는 주석 처리되어 있어 실제 발생 조건을 확인해야 함 |
| `0x13` / `0x14` / `0x15` / `0x16` | 8 → 16A | 튜닝 진행 55 / 65 / 75 / 100 단계 |
| `0x17` / `0x19` | 8 → 16A | 직접 튜닝 진행 표시 / 튜닝 종료 |
| `0xA8` / `0xAA` | 8 → 16A / 16A → 8 | 시작 알림 / 확인 |
| `0xA9` / `0xAB` | 16A → 8 / 8 → 16A | 상태 요청 / 응답 |
| `0xAC` / `0xAD` | 8 → 16A / 16A → 8 | 업로드 완료 표시 요청 / 확인 |

ATmega8은 시작 알림을 확인받을 때까지 최대 20회 전송하며, 상태 요청에는
응답한다. ATmega16A는 상대를 아직 확인하지 못한 정지 상태에서 상태
요청을 보낸다. 상대를 한 번 확인한 뒤의 지속적인 연결 감시나 제어 명령
타임아웃은 확인되지 않는다.

업로드 스크립트가 플래시와 EEPROM 등을 검증한 다음 EEPROM의 예약 마커를
기록하면 ATmega8이 `0xAC`를 재전송한다. ATmega16A가 안전한 표시 조건에서
`UPLOAD COMPLETE`를 20틱(명목 약 2.016초) 표시하고 `0xAD`를 보내면,
ATmega8이 마커를 지운다. `ATMEGA8 ONLINE`은 30틱(명목 약 3.024초)이며,
시작/응답을 뜻할 뿐 업로드 성공 자체는 아니다. 운전·튜닝·오류 조건에
따라 표시는 지연되거나 취소될 수 있다.

## 7. 명시적으로 현재 미확인 또는 비활성인 기능

- ATmega16A의 `timeprog.c` 포함, 시간 설정 표시, 스위프 동작 및 관련 키
  처리의 상당 부분은 주석 처리되어 있다. EEPROM 필드와 테이블의 존재만으로
  현재 운전 중 시간 제한이나 스위프가 작동한다고 볼 수 없다.
- ATmega8의 이동평균 필터 계산, `ucError_flag`를 이용한 튜닝 중단,
  워치독 초기화 호출 및 SPI 출력 함수의 실제 사용은 현재 실행 경로에서
  확인되지 않는다.
- PLL 잠금 신호의 소프트웨어 판정, 잠금 실패 타임아웃, 목표 주파수의
  물리 단위 설정, 전류 센서의 암페어 보정, 운전 명령의 통신 타임아웃은
  이 소스에서 확인되지 않는다.
- 회로도에는 LM565, 게이트 드라이버 및 출력 회로가 있지만, 이 정적 분석은
  위상 여유, 공진, 구동 파형, 전압/전류 한계 또는 부하 보호를 검증하지
  않는다.

## 9. 후속 검증 및 개선 순서

1. **기준 확보:** 실제 보드 개정판, 두 크리스털, SW3, 결선, 펌웨어와
   EEPROM 백업을 확인한다. 현재 설정값과 오류 발생 조건을 기록한다.
2. **안전 요구 정의:** 운전·정지·튜닝·통신 끊김·과부하·리셋 각각에서
   출력이 어떤 상태여야 하는지와 독립 하드웨어 보호의 역할을 확정한다.
3. **비구동 시험:** 출력 구동을 안전하게 분리한 상태에서 UART, ADC 입력,
   디지털 저항 코드, 주파수 카운트와 EEPROM 경계값을 검증한다. 장비
   연결 및 측정은 회로와 장비에 익숙한 사람이 수행해야 한다.
4. **오류 주입:** I2C NACK/단선, UART 오류·누락, 전원 재인가, EEPROM
   손상, 과부하 입력을 시험해 정지와 복구 경로를 관찰한다.
5. **제어 성능:** 안전 조건이 확보된 후 `CNT`, LM565 주변 신호, 전류와
   저항 코드의 관계 및 잠금/튜닝 재현성을 계측하고 목표 주파수·허용
   오차·응답시간을 정의한다.
6. **수정과 회귀:** 가장 위험한 확인 항목부터 소규모로 수정하고, 각
   변경에 호스트 테스트와 실제 보드 검증을 추가한다. 현재 업로드 검증과
