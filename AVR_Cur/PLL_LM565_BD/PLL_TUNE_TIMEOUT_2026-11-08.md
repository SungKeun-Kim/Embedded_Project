# 자동 튜닝 1분 제한과 ATmega8 검증

후속 변경: [START 3초로 시간 초과 해제](./PLL_TIMEOUT_RESET_2026-11-08.md). 두 MCU에 이 후속 수정본을 모두 기록하면 시간 초과에 한해 버튼으로 해제할 수 있다. 아래 전원 재시작 설명은 최초 구현 이력이다.

2026-11-08, 진동자 미연결 상태에서 자동 튜닝이 끝나지 않는 사용자 보고를 반영했다.

**최신 상태: 아래 수정본은 2026-11-08 ATmega8에 업로드·검증 완료했다.** 하단의 미기록 문구는 업로드 전 작업 이력이다. 실물의 60초 중단과 LCD 표시 여부는 별도 확인이 필요하다.

## 변경 동작

- START를 약 3초 누르는 동작은 그대로다. 그 뒤 ATmega8이 출력 준비 명령 `0x1C`를 받으면 전체 제한 시간을 시작한다. **PWM 준비 시간을 포함해 약 60초**다.
- 16MHz와 Timer0 5.12ms 기준 `11718`틱, 명목 59.99616초를 사용한다. 실제 차단 시간에는 통신·스케줄링과 하드웨어 클록 오차가 더해진다.
- 시간 안에 최소점을 확인하지 못하면 성공 저장을 하지 않는다. `0x12`로 실패를 알리고 ATmega16A의 기존 `Tuning ERROR`/출력 차단 경로를 실행한다. 실패를 정상 완료로 표시하지 않는다.
- AD5280은 **튜닝 직전 확인된 실제 코드**로 복귀한다. 이 값이 운전 중 보정으로 EEPROM의 초기 코드와 달라졌어도 직전 값을 기억한다.
- 실패 뒤 메인 루프가 복귀값을 EEPROM 초기값으로 다시 덮어쓰지 않도록 처리했다.
- 기존 오류 유지 정책을 따른다. 실패 후 자동 재운전하지 않으며 재시작이 필요하다. 정상 대기의 미세 출력으로 복귀하는 기능과 오류 차단은 다르다.
- 최소점을 찾았어도 종료 시각까지 EEPROM 저장·검증 여유 약 328ms가 남지 않았다면 저장을 시작하지 않고 실패 처리한다.
- 기존 EEPROM 쓰기의 유효 표시 직전 검사도 유지한다. 평탄한 전류 응답으로 시간 초과하는 시험에서는 **EEPROM 쓰기 횟수 0**, 기존 512바이트 전체 동일함을 확인했다.

시간 제한은 진동자 미연결을 직접 검출하는 기능은 아니다. CNT에 자유발진 신호가 남는 경우에도 끝없이 탐색하지 않도록 하는 제한이다.

## 업로드 완료 표시 확인

현재 절차는 다음과 같다.

1. 업로드 스크립트가 Flash/EEPROM과 퓨즈·잠금값을 검증한다.
2. 그 뒤에만 EEPROM `0x1F8~0x1FF`에 업로드 알림 표식을 기록·검증한다.
3. ATmega8이 표식을 읽고 `0xAC`를 보낸다. 확인 응답 전에는 약 512ms마다 재전송한다.
4. ATmega16A가 정지·비튜닝·비오류 상태일 때 LCD 둘째 줄에 `UPLOAD COMPLETE`를 **20틱, 약 2.016초** 표시한다.
5. ATmega16A의 `0xAD` 응답을 받으면 ATmega8이 알림 표식을 지운다. LCD는 시간이 지나면 원래 둘째 줄로 복귀한다.

운전/튜닝/오류 중에는 표시를 보류한다. 첫 통지나 첫 확인 응답이 유실되어도 재전송하고, 중복 통지를 받아도 표시 시간을 계속 연장하지 않는 통신 모의 시험을 통과했다. **실제 LCD 화면을 원격으로 관측한 것은 아니므로, 실제 업로드 후 화면 확인은 별도다.**

## ATmega8 스택과 메모리

IAR 함수별 스택 목록과 링크 결과를 사용해 메인 호출 경로에 활성 ISR 1회의 사용량을 더했다. `phase_find_minimum → measure_code`의 함수 포인터 호출과 길어서 줄이 나뉜 함수명도 검사에 포함했다. `memset`은 링커에 기록된 말단 함수 스택 정보를 사용했다. 해석하지 못하는 호출 경로가 있으면 검사에 실패하도록 했다.

| 항목 | 계산된 사용량 | 추가 여유 | 예약 공간 | 결과 |
|---|---:|---:|---:|---|
| CSTACK | 64바이트 | 16바이트 | 192바이트 | 통과 |
| RSTACK | 22바이트 | 16바이트 | 128바이트 | 통과 |

수정본 Flash 이미지는 **6,066/8,192바이트**, SRAM은 스택 예약을 포함해 **444/1,024바이트**다. 이 검사는 현재 활성 인터럽트의 비중첩 실행과 컴파일 목록을 전제로 하며 모든 종류의 메모리 오류나 실물 고장을 보장하는 검사는 아니다.

이제 [빌드 스크립트](./.vscode/build-iar.ps1)가 ATmega8과 ATmega16A 모두 스택을 검사한다. 따라서 업로드 스크립트에서도 스택 검사에 실패한 빌드는 기록하지 않는다.

## 시험 결과와 기록 상태

- C 시험 12개 통과. 평탄 응답 60초 중단, 타이머 순환, 직전 코드와 EEPROM 코드가 다른 경우의 복귀, 시간 부족 시 저장 금지, 시간 안에 성공하는 경우, 업로드 통지/확인 응답 유실·재전송을 포함한다.
- ATmega8 IAR 오류 0/경고 0, 스택 검사 통과.
- ATmega16A IAR 오류 0/기존 경고 4개, 스택 검사 통과. HEX SHA-256은 기존에 기록한 스택 수정본과 동일하다. ATmega16A 재기록은 필요 없다.
- **현재 수정본은 아직 장비에 기록하지 않았다.** 사용자 확인 결과 ISP가 ATmega16A에 연결되어 있다. ATmega8으로 옮겨 기록해야 1분 제한이 적용된다.
- 수정 전 백업: `.build/before_tune_deadline_20261108_000422/`

### ATmega8 수정본 업로드 완료

사용자는 위 ATmega16A 재업로드 후 정상 상태이며 부저가 울리지 않는다고 확인했다. 이어 ATmega8 연결·전원·REMOTE 정지를 확인한 뒤 업로드를 요청했다.

- 모의 시험 12개 통과. 60초 제한, 직전 코드 복귀, 시간 초과 시 EEPROM 쓰기 0회, 완료 알림 재전송을 포함한다.
- IAR 빌드 오류 0/경고 0, CSTACK 및 RSTACK 검사 통과.
- Flash 6,066바이트 기록 및 두 차례 읽기 검증 통과.
- EEPROM 512바이트 백업·복원·검증 통과. 기존 유효 설정은 AD5280 코드 233, 구형 유효 표식 `0x55`였고 새 저널 슬롯은 비어 있었다.
- 퓨즈와 잠금값 보존 확인 후 완료 알림 표식 8바이트를 기록·검증했다.
- 백업: `.build/backups/ATmega8_upload_20261108_003632_23ef7e9f/`
- 실행 기록: `.build/atmega8_timeout_upload_20261108_003630.log`
- HEX SHA-256: `01A6077F95B260DBECAEF2D3F99B394667AB2CB729547ED915483B6A9A0E4AE5`

실제 LCD의 `UPLOAD COMPLETE` 표시와 시간 초과 동작은 사용자 확인이 남아 있다. 현재 시간 초과는 기존 오류 경로로 처리하므로 출력 차단과 함께 `Tuning ERROR` 및 부저가 발생한다. 단순 STOP 대기 복귀와는 다르며, 오류 상태를 해제하려면 두 MCU의 전원을 재시작해야 한다. 이번 작업에서는 이 기존 오류 정책을 바꾸지 않았다.
