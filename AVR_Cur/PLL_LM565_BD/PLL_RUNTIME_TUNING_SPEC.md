# 운전 중 작업 분류와 위상 보정

2026-11-07 사용자 요청에 따른 구현이다. 초기 자동 튜닝과 운전 중 보정은 별개다.

## 현재 동작

- 초기 자동 튜닝: START 약 3초 유지 → PWM 약 50% → 전류 최소점 반복 확인 → 높은 주파수 쪽 한 칸 → EEPROM 저장. [초기 튜닝 사양](./PLL_AUTOTUNE_SPEC.md) 참조.
- 운전 중 보정: 명목 0.2A 상승을 감지 → **낮은 주파수 쪽 한 칸** → 안정 시간을 둔 뒤 약 3초의 비교 가능한 구간 관찰 → 개선되면 다음 한 칸 → 악화/불분명하면 직전 확인 위치로 복귀.
- 운전 중에는 높은 주파수 쪽 한 칸 오프셋을 추가하지 않는다. 최초 시험 방향은 항상 코드 감소 방향이다.
- 확인된 운전 보정값은 RAM에만 둔다. 정상 정지와 재시작 때는 유지한다. 전원을 다시 켜거나 초기 자동 튜닝을 실행하면 EEPROM의 초기 설정을 기준으로 새로 시작한다.
- 정상 정지 상태의 미세 출력은 유지하며 그 상태에서는 AD5280 탐색을 하지 않는다. ‘무부하로 계속 출력’은 RUN 상태의 저전류 안정 출력을 의미한다.

## 전류 환산과 판정

사용자가 보는 전류는 패널의 아날로그 DC 전류계다. ADC 실측 대응값은 아직 없다. 이번 값은 회로도와 [ACS712 데이터시트](https://www.allegromicro.com/~/media/files/datasheets/acs712-datasheet)에 따른 **명목 환산**이다.

ACS712ELCTR-20A-T의 명목 감도는 100mV/A다. 도면의 R100=2kΩ, R101=10kΩ, R103=57.6kΩ을 반영하고 D100의 동저항은 제외하면 기울기는 다음과 같다.

```text
분압/부하 이득 ≈ (10 / 12) × (57.6 / (57.6 + 1.667)) ≈ 0.810
ADC 변화/A ≈ 0.100V × 0.810 × 1024 / 5V ≈ 16.6단계/A
0.2A 변화 ≈ ADC 3.3단계
```

계산에는 ADC 한 단계를 16으로 나타내는 Q4 정수를 사용한다. `RT_TRIGGER_Q4=53`, `RT_GAIN_Q4_PER_A=265`다. 이는 ADC의 실제 하드웨어 분해능이 늘었다는 뜻은 아니다. 필터링과 여러 주기 평균을 통해 작은 변화를 비교한다. 다이오드 동저항·온도 변화·부품 오차 때문에 실제 전류계에서 정확히 0.2A가 되는지는 실측 보정해야 한다.

한 칸의 개선 판정은 ADC 1단계보다 큰 감소(명목 약 0.060A)를 요구한다. 개선이 모호하면 직전 위치로 복귀한다. 절대 과전류 문턱은 기존 ATmega8 ADC 450, ATmega16A ADC 500을 유지했으며 **5.5A로 교정된 차단값은 아니다.**

## 작업 구분

약 5.12ms마다 최신 ADC 값을 읽고, 정수 필터를 적용한다. 전류 상승 시작 사이의 간격을 관찰한다. 약 0.15A의 상승/하강 히스테리시스와 약 102ms의 최소 검출 간격을 사용한다.

| 관측 조건 | 분류/동작 |
|---|---|
| 상승 간격 약 1초 이내가 3회 연속 | 연속 반복 작업 후보 |
| 상승 간격 약 2초 이상이 3회 연속 | 프레스형 후보, 보정 금지 |
| 1~2초, 관측 부족, 불규칙 | 미확정 |
| 대기 전류 기준보다 명목 0.8A 이내이고 3초간 변동 폭 약 0.1A 이내 | 저전류 안정 출력 후보 |

대기 기준은 RUN이 꺼진 미세 출력 상태에서 3초간 안정된 값을 얻어 RAM에 기록한다. **0A 보정값이 아니며 실제 무부하 판정을 보장하지 않는다.** 기동 직후 바로 RUN으로 들어가 대기 기준이 없으면 저전류 안정 출력 분류는 보류하고, 연속 반복 패턴 분류만 가능하다.

연속 작업은 3초 구간에 최소 3개의 완료된 전류 피크가 있어야 하며, 주기별 피크의 평균을 비교한다. 구간 내 반복 간격이 25% 이상 불규칙하거나 이전 기준과 반복 속도가 크게 다르면 비교를 폐기/재설정한다. 저전류 안정 출력은 평균 전류를 사용한다. 대표 전류가 기준보다 명목 0.2A 이상 상승한 유효 구간이 두 번 확인되면 탐색한다.

## 한 칸 보정과 중단

1. 초기 저장 코드에서 낮은 주파수 쪽 최대 3칸, 전체 코드 221~249 안에서만 이동한다.
2. 코드 적용 후 AD5280 RDAC를 읽어 쓰기값을 확인한다.
3. 약 819ms 안정 시간을 두고 약 3초의 유효 관찰 구간을 수집한다. 연속 작업의 패턴을 다시 확인해야 하면 더 오래 걸릴 수 있다.
4. 작업 종류/반복 간격이 비교 가능하고 전류가 충분히 줄었으며 주파수가 반대 방향으로 증가하지 않았을 때만 채택한다. 주파수 방향 비교는 계수 1단계의 오차를 허용한다.
5. 개선되지 않거나 판단이 불가능하면 마지막으로 확인된 위치로 복귀한다. 관찰 중 대표 이전 피크/평균보다 명목 0.2A를 초과하는 큰 악화는 3초 종료 전에도 복귀한다.
6. 탐색이 끝나면 10초간 재탐색을 보류하고 새 기준 구간을 확보한다.

사용자가 제시한 운전 주파수 범위 19.2~20.6kHz를 적용했다. CNT=발진 주파수/8, 16MHz MCU, 약 256ms 측정 조건에서 계수 614~660을 허용한다. 이는 약 31.25Hz의 계수 해상도를 고려한 범위다. 주파수 이탈, ADC 불능, 기존 과전류, I2C 실패는 제어 오류로 전달한다. CNT는 발진기 출력 계수이며 피드백 정상/PLL 잠금을 직접 증명하지 않는다.

3초 동안 CPU를 대기시키지 않는다. 측정, 통신, 보호와 시간 판정을 계속 수행하는 상태 머신이다. 샘플이 누락되면 비교를 버리고 미확인 위치를 되돌린다.

## 두 MCU의 역할과 업로드 순서

ATmega16A는 노브의 목표 PWM과 실제 PWM이 같고 약 1초 동안 안정되었을 때 `0xB0` 허가를 약 100.8ms마다 전송한다. 노브/PWM 변경, 정지, 초기 튜닝, 오류 때는 `0xB1` 보류를 보낸다. ATmega8은 약 512ms간 새 허가가 없으면 보정을 중단하고 미확인 시험 위치를 복귀한다. 이 통지는 기존 정지 명령과 다른 수신 경로에서 처리하여 정지 명령을 덮지 않는다.

따라서 **ATmega8만 먼저 기록한 상태에서는 구형 ATmega16A가 운전 중 보정을 허가할 수 없다.** ATmega16A도 이 버전으로 갱신해야 새 기능이 동작한다. 새 초기 튜닝 역시 준비 명령 `0x1C`를 먼저 받아야 실행되므로 구형 16A의 튜닝 명령은 오류 처리한다. 준비되지 않은 출력에서 새 탐색을 실행하지 않기 위한 동작이다.

기존 EEPROM 초기 코드와 퓨즈는 업로드 과정에서 보존한다. 이번에 읽은 장비는 초기 코드 233, 구형 주파수 바이트 105, 구형 유효표시 0x55, 새 저장 슬롯은 빈 상태였다. lfuse=0xFF, hfuse=0xC9, lock=0xFF였다.

## 검증과 남은 확인

호스트 시험은 연속/프레스/미확정/저전류 안정 분류, 임계값 미만 변화, 여러 칸 개선과 악화 복귀, 정지/허가 해제/샘플 누락/주파수 이탈, 3칸 한계, 반복 속도 변경, 잡음, 장시간 관측을 포함한다. 기존 초기 튜닝·저장·LCD·알림·보호 시험도 함께 실행한다.

이번 빌드에서 C 시험 12개와 업로드 스크립트의 모의 시험이 통과했다. IAR 빌드는 ATmega8 오류/경고 0개, ATmega16A 오류 0개/기존 미사용 변수 경고 4개다.

| ATmega8 메모리 | 사용/예약 | 전체 |
|---|---:|---:|
| Flash 이미지(빈 구간 채움 포함) | 5,839바이트 | 8,192바이트 |
| SRAM(스택 예약 포함) | 440바이트 | 1,024바이트 |
| 위 SRAM 중 작업 분류/보정 상태 구조체 | 65바이트 | — |

스택 예약은 CSTACK 192바이트, RSTACK 128바이트로 늘렸다. SRAM의 나머지 584바이트와 별개로, 실제 최악 경로의 스택 사용량은 실물 장시간 운전에서 추가 확인할 수 있다.

센서 환산의 정확도, 실제 주파수 변화 방향, 부하 변화와 위상 보정 효과의 분리, 출력 진폭과 브릿지 부품 전압/발열은 실물에서 확인해야 한다. 전류 패턴만으로 모든 압력 변화를 구별할 수 없으며 이 펌웨어로 고장 방지가 입증된 것은 아니다.
