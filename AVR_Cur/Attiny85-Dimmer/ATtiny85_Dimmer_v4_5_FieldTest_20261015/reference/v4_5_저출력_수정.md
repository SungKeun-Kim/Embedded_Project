# v4.5 — 기존 저출력 위상 범위 및 ON 기준 복원

작성일: 2026-10-14

후속 사용자 시험: 60Hz에서 최저출력 구간이 크게 개선되어 기존 펌웨어와 같다고 보고했다. 실제50Hz는 미시험이다. 현재 판단과 남는 부하측 차이는 `v4_5_50Hz_추론검토.md` 참고. 아래 수정 당시 검증 한계와 시험 이력은 보존한다.

## 반영한 사용자 시험 결과

동일한 보드에서 MCU만 교체하여 비교했다. v4.4도 볼륨 약1/10회전까지는 기다려도 출력0이며, 이후 약10부터 올라가는 것처럼 보였다. 기존 펌웨어에도 무반응 구간은 있지만 더 짧고, 출력 시작이 바닥부터 부드러웠다. v4.3에서 START·운전 중 볼륨 변경 시 에러·STOP→START는 정상으로 보고됐다.

v4.4는 최고출력만 수정하여 저출력 조건은 바뀌지 않았었다. 이번에는 실제로 다른 두 저출력 조건을 수정했다. 입력 전압 측정을 작업의 선행 조건으로 요구하지 않고, 같은 입력에서 이전 코드와 새 코드의 차이를 비교했다.

## 확인된 코드 차이와 해석

| 항목 | 기존 백업 소스 | v4.4 | v4.5 |
|---|---:|---:|---:|
| OFF에서 ON으로 전환하는 ADC 상한 | 899 | 890 | **899** |
| OFF 판정 | 900 이상 | 900 이상 | 900 이상 |
| 입력 최대 지연 포화 | 880 이상 | 880 이상 | 880 이상 |
| 최저출력 지연 기준(분모332) | 308 | 290 | **308** |
| 최고출력 지연 기준 | 128 | 133 | 133 |
| 게이트 기본 폭 기준 | 20 | 20 | 20 |
| 게이트 종료 후 기준 여유 | 2 | 20 | **16＋최소 여유 보정** |

ON 진입 문턱을890으로 바꾸면서 ADC891~899는 기존에서 켜지고 새 코드에서는 꺼지는 구간이 됐다. 5V 기준으로 기존 최초ON(899)과 v4.4 최초ON(890)은 약44mV 차이다. 실제 볼륨 회전각과 입력 전압 사이의 관계를 측정하지 않았으므로 이 차이가 약12% 회전각 전체를 설명한다고 단정하지 않는다.

최저출력 점화를308→290으로 앞당긴 것은, 게이트가 켜질 때의 최소 전력을 높일 수 있다. 사용자 관찰과 부합하는 변경이지만, 실제 부하 전압10%라는 수치를 코드만으로 계산하거나 확정하지 않는다. 이번에308을 복원하여 낮은 출력의 시작 위상을 이전 범위로 되돌린다. 실제 입력이880~899이면 최저 위상으로 고정되는 부분은 기존과 동일하게 남는다.

백업 HEX `backup/pre_50_60hz/firmware.hex`도 역어셈블했다. 바이트 주소0x3EC~0x3F2의 ADC 비교값은0x0384=900이며,0x400~0x408에서0x0370=880을 비교한다. 백업 HEX의 SHA256은 `6640CA968AEBD6B0D68D8962ED8403B33289EE6736256F6EFE236C01FA7294A0`이다. 사용자가 실물 MCU에 기록한 HEX와의 해시 일치까지 확인한 것은 아니다.

## 종료 여유를 확보한 방법

앞선 설명에서308을 쓰려면 여유를2틱으로 줄여야 한다고 한 것은 게이트 폭20을 끝까지 유지한다는 전제였다. 낮은 출력에서만 게이트 폭을 제한하면 시작 위상과 종료 여유를 별도로 정할 수 있다.

```text
점화 시작 = 반올림(실측 반주기 × (출력 위상 + 2) / 332)
기본 폭 = 반올림(실측 반주기 × 20 / 332)
종료 여유 = max(반올림(실측 반주기 × 16 / 332), 반주기/32 + 2 + 3)
게이트 종료 = min(점화 시작 + 기본 폭, 실측 반주기 - 종료 여유)
```

위 계산의 반주기는 최근 실측값과 필터링한 값 중 작은 값이다. `periodTolerance()`의 주기 단축 허용량과 추가2틱 지터 뒤에도 최소1틱이 남도록 하한을 둔다. 단순16/332 반올림만으로는 일부 짧은 반주기에서 이 조건이 부족함을 시험에서 찾아 보강했다.

| 최저출력 예시 | 60Hz,333틱 | 50Hz,400틱 |
|---|---:|---:|
| 점화 시작 | 311틱 /7.775ms | 373틱 /9.325ms |
| 게이트 종료 | 317틱 /7.925ms | 381틱 /9.525ms |
| 게이트 폭 | **6틱 /150µs** | **8틱 /200µs** |
| 다음 검출 엣지까지 여유 | **16틱 /400µs** | **19틱 /475µs** |

명목25µs 틱의 반올림 예시이며 실제 AC0V가 아닌 PB2 검출 상승엣지 기준이다. 게이트 폭을 유지할 수 있는 중·고출력에서는 기존 기본 폭500/600µs를 사용한다. 주파수에 따라 Timer1 틱 길이를 바꾸지 않고 틱 수를 계산한다.

짧은 게이트 펄스는 새로운 실보드 확인 항목이다. MOC3021 계열 제조사 자료도 LED 펄스 폭에 따른 트리거 전류 특성을 다룬다. 이 자료만으로 실제 주 트라이악/정류부/초음파 부하가150µs에서 안정적으로 점화된다고 보증할 수는 없다. [onsemi MOC3021M 계열 데이터시트](https://www.onsemi.com/pdf/datasheet/moc3023m-d.pdf).

ON 문턱 복원으로 히스테리시스도 제거했다. 기존과 같은 입력 판정이지만900 주변에 리플이 있으면 ON/OFF 반복 가능성이 있으므로 시험에서 확인한다. MCU 교체 비교 사실을 무시하고 입력 회로 문제로 단정하지 않는다.

## 유지한 동작

- 최고출력133＋offset2, 측정 반주기에 비례한50/60Hz 대응.
- 부팅 시 명목1초 안정화, 이후 온전한 반주기8회 검증.
- SG3525 시작 대기 제거, ADC 명목10ms 갱신, 첫 반주기는최저출력.
- 유효 반주기마다 최대10기준틱씩 출력 상승. 범위가 늘어 최소→최대는18단계(60Hz 약150ms,50Hz 약180ms).
- 게이트 종료/새 ZC 검출/동기화 손실/과도한 검출 폭의 차단.
- 메인 MCU 소스와퓨즈 E2/DF/FF. 메인 MCU 일반RUN 경로는START 후 약2초부터 검사하며 이후 약100ms마다 검사한다.

## 검증 결과

- 빌드 성공: Flash2106/8192바이트, 정적RAM46/512바이트(스택 별도).
- 소스 호스트 회귀60주파수/클럭/입력 조합,60펄스폭 조합 통과.
- 전체250~500반주기틱 ×176출력 위상: 다음 주기가 허용량만큼 짧고 추가2틱 지터가 있어도 게이트 종료 여유 확보. 최소 게이트4틱 이상.
- 50/60Hz ADC1023→61→1023 전 구간 단조 변화와ON=899/OFF=900 경계 통과.
- ADC700~899에서 기존2단계 정수변환 소스와 새 저출력 위상 차이2기준틱 이내 확인.
- 응답24조합: 첫 게이트35ms 미만, 최대출력 게이트220ms 미만(동기화 후START 기준).
- 실제 AVR 바이너리42조합 통과: 기존36조합＋4390mV(ADC약898)에서 새ON 동작6조합. 최저출력 단축 펄스,종료 여유,첫START/재START,정상 펄스 수 검증.
- ISR본문133클럭＋원자구간32클럭＋진입 등10클럭=보수적175/200클럭 이내.
- 시뮬레이터의 Timer1 보완 조건과 아날로그 부하 미모사 한계는 `test/README` 참고.

이 결과는 실제 출력 전압이 정확히0부터 부드럽게 올라간다는 검증이 아니다. 부하 출력, 점화 성공, 깜빡임, 메인 MCU 전류 피드백은 사용자 재시험이 필요하다.

## 파일과 다음 시험

`R_Type_2+133Tick_Min308_Guard16_50_60Hz_v4_5.HEX`와 루트 `firmware.hex`는 같은 바이너리다. 직전 버전은 `backup/v4_4_before_low_range_fix/`에 보존했다. 보드 업로드는 수행하지 않았다.

기존과 같은 보드에서 볼륨 최저부터 아주 천천히 올려 무반응 범위와 최초 출력 크기를 비교한다. 낮은 위치에서 잠시 유지했을 때 깜빡임/출력 누락이 생기는지도 확인한다. 마지막으로50% 이상START,운전 중 볼륨 변경,STOP→START의 오류 재발 여부를 확인한다. 50Hz 실제 부하 시험은 아직 수행하지 못했다.
